# 质量评价旧版与 V2：5 篇 PDF 双模型对照分析

> 日期：2026-10-12  
> 样本：`Test_QA_New` 中资产 17～21，共 5 篇 PDF  
> 方法：QUADAS-2，共 14 个信号问题/篇  
> 模型：DeepSeek V4 Flash、Qwen3.7-Flash  
> 真实调用：旧版 10 次；V2 40 次；两轮均未重试  
> 人工参考：Codex 阅读 30 页 PDF 全文后形成的单人保守判断，不是正式医学或方法学金标准。

## 1. 执行结论

这次对照说明旧版和 V2 各自解决了不同问题，但当前 V2 尚未达到“又安全、又充分回答”的状态。

- **旧版更敢回答、便宜，但容易无依据地肯定。**140/140 条都返回合法 JSON，Token 仅为 V2 的约 1/6；但它会在缺少综述问题时仍然判断适用性高/低，并会把“文献未报告问题”误当成“没有问题”。
- **V2 更安全、更可审计，但明显过度保守。**非法证据引用会被关闭失败，适用性和盲法等缺乏依据时能正确保持不清楚；但在人工认为可以明确回答的 34 个问题上，双模型平均一致率只有 39.71%。
- **不能直接恢复旧版，也不应立即全量开放当前 V2。**更合理的方向是保留 V2 的全文证据编号、页码审计和关闭失败机制，同时提高按信号检索召回率，并给模型更明确的 QUADAS-2 判断规则。

综合判断：V2 的架构方向正确，工程安全性显著优于旧版；当前主要短板不是全文长度，而是“检索到什么证据”和“如何依据证据回答具体信号问题”。

## 2. 两种链路如何评价

### 旧版

1. 每篇文献只读取开头 8,000 字符；
2. 将 14 个 QUADAS-2 问题和这段文本一次性发送给模型；
3. 每篇、每模型一次调用，共 10 次；
4. 只校验 JSON、信号 key 和答案选项，不验证证据摘录是否真的来自原文，也不验证页码。

旧版 8,000 字符实际覆盖范围：

| 资产 | PDF 总页数 | 旧版到达的最后页 | 明显未进入旧 Prompt 的内容 |
|---|---:|---:|---|
| 17 / Chen | 4 | 3 | 第4页讨论尾部与参考文献 |
| 18 / Lei | 5 | 4 | 第5页讨论尾部与参考文献 |
| 19 / Kandil | 7 | 2 | 第3页后的统计结果、cut-off、讨论 |
| 20 / Huang | 7 | 3 | 第4页后的结果、局限性与讨论 |
| 21 / Liu | 7 | 3 | 第4页检测流程、第5页缺失数据和后续结果 |

### V2

1. 提取并分块完整 PDF；
2. 按领域和信号问题检索候选证据；
3. 每篇分 4 个领域、每领域调用两个模型，共 40 次；
4. 模型只能引用受控证据编号；编号越界、数量超限或结构错误时转为“需人工判断”；
5. 通过校验的证据可以回溯到原文、页码和片段哈希。

|---|---:|---:|

| 期望模型信号结果 | 140 | 140 |
| 结构/协议有效 | 140（100%） | 135（96.43%） |
| 协议失败并转人工 | 0 | 5（3.57%） |
| 有证据的明确结果 | 未验证；模型全部作答 | 34（24.29%） |

| Prompt Token | 54,860 | 419,966 |
| Completion Token | 16,498 | 10,502 |
| Total Token | **71,358** | **430,468** |

V2 的总 Token 是旧版的 **6.03 倍**。本轮两者实际执行时间都在约两分钟量级，但样本太小、缓存比例不同，不能据此判断生产吞吐量相同。

旧版的 100% 是“能解析出答案”，不等于“证据正确”。旧版允许模型自由生成证据摘录和页码，系统没有把它们与 PDF 原文匹配，因此不能与 V2 的协议有效率作等价比较。

## 8. 关键案例

### 8.1 V2 明显优于旧版：适用性问题

项目没有填写研究问题上下文，人工无法判断患者、指标试验和参考标准是否与综述问题匹配。旧版仍大量输出“高”或“低”，三个适用性问题几乎全部错误；V2 按规则返回不清楚，30 个模型结果中全部与人工参考一致。

### 8.2 V2 明显优于旧版：Liu 的分析缺失

Liu 第 5 页明确报告细菌感染组、未感染组和对照组存在血清样本缺失。旧版对该文只看到第 3 页，Qwen 判断“所有患者均纳入分析”，DeepSeek返回不清楚。V2 能检索第 5 页：DeepSeek据此判断“否”，与人工参考一致；Qwen仍只引用入组人数并判断“是”。这证明全文覆盖解决了信息缺失，但检索/模型选择仍可能忽略更关键的反证。

### 8.3 旧版看似完整但共同错误：不恰当排除

Chen、Lei、Huang均排除了会影响临床代表性的常见患者类型或既往治疗病例。旧版两个模型在三篇中都倾向于把“明确写了排除标准”误解成“排除合理”，该信号问题双模型均为 0/5。V2有所改善，但 Qwen仍容易把减少混杂等同于避免选择偏倚。

### 8.4 V2 过度保守：Kandil 后半部分

Kandil 的旧版输入只覆盖前 2 页，确实看不到第 3 页后的阈值和结果；V2虽然覆盖全文，但在时间间隔、全部接受参考标准、相同参考标准和全部纳入分析上两个模型仍同时返回不清楚。全文中已经报告血液与CSF同时采集、全部对象接受检查、三组各30例进入分析，因此这些问题具备回答条件。问题在信号级检索和判定规则，而不是全文不存在。

### 8.5 两模型都不可靠时必须保留人工审核

Huang、Liu 的“不恰当排除”和 Liu 的“全部纳入分析”都出现有证据但判断相反。双模型不能自动充当真值；应把冲突作为人工审核优先级，而不是随机选一个模型或以多数票自动确认。

## 9. 误差来源

### 旧版

1. 8,000 字符通常只覆盖前 2～4 页，遗漏结果、缺失数据和讨论中的局限性；
2. 一次回答14个问题，模型容易使用同一段摘要泛化到不同信号；
3. 没有研究问题上下文仍强制评价适用性；
4. 自由文本证据和页码没有服务端校验；
5. 容易把“未报告”解释成“没有偏倚”。

### V2

1. 信号问题的候选证据召回不足，尤其是流程、失访、完整分析和参考标准；
2. 领域级证据目录容易发生跨信号引用，造成5条协议失败；
3. Prompt 没有充分定义“是/否/不清楚”的证据门槛；
4. DeepSeek过度使用缺少研究上下文作为非适用性问题的拒答理由；
5. Qwen更愿意作答，但容易由样本量一致、明确排除标准等表面信息得出过度肯定结论；
6. 每领域重复发送较大证据目录，Token成本较高。

## 10. 建议方案

### P0：在继续灰度前修正

1. **研究问题上下文成为 QUADAS-2 评价前置条件。**至少填写目标人群、指标试验、目标疾病和参考标准；未填写时三项适用性保持不清楚。
2. **为每个信号问题写清判定规则。**例如：
   - 未明确连续/随机入组，不得判断“是”；
   - 未报告盲法，必须判断“不清楚”；
   - 明确排除标准不等于避免不恰当排除，必须评估代表性；
   - 没有明确说明完整分析，不能仅凭入组人数推断“是”；
   - ROC/约登指数从当前样本选出的阈值判定为“否”。
3. **增强负向证据检索。**提高“排除、缺失、脱落、未检测、培养阴性、未纳入、失访、抗生素治疗”等内容的召回与排序。
4. **按信号隔离证据编号。**避免模型看到领域内其他问题的编号并跨信号引用。
5. **双模型冲突必须进入人工审核。**特别是任一模型引用到缺失、排除或不一致信息时。

### P1：降低成本并提高可用回答覆盖

1. 先做轻量证据检索，仅对候选不足的信号扩展邻块或增加检索轮次；
2. 同一领域共享静态证据目录时利用供应商缓存，避免重复发送；
3. 将“缺少研究上下文”和“原文未报告”区分为不同原因，便于前端提示用户；
4. 建立至少20～30篇、双人复核的人工参考集，分别统计明确问题准确率和不清楚校准率；
5. 修正 Huang、Liu 的 PDF 元数据标题回填，避免使用内部标题 `JY11A01程歆琦`、`JY7A01李伟述评`。

## 11. 最终建议

当前不要把旧版重新设为默认，也不要把 V2 直接开放给全部用户。

建议继续保留：

- V2 全文分块；
- 证据编号和页码回溯；
- 非法引用关闭失败；
- 人工确认作为最终结果。

下一次开发重点应从“继续扩大上下文”转向“信号级证据召回 + 明确判定规则”。完成 P0 后，先用本次已经产生的固定输出和本地 mock 回归，不需要再次付费调用；只有准备进入白名单验收时，再单独获得真实模型测试授权。
