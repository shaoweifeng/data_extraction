# 性能验收与上线待办

> 更新日期：2026-09-29
> 详细数据模型、阶段记录和回滚方案见 `docs/screening-database-storage-plan.md`；本文件只保留仍有执行价值的性能结论和上线待办。

## 当前结论

文献初筛数据库化阶段 1—12 的本地工程工作已经完成。运行时列表、统计、去重详情、AI 初筛、人工审阅和导出均不再扫描单篇 XML/JSON；单篇 XML 与单篇 AI JSON 已退出主数据路径。

当前结构已经具备：

- 原始索引保存在私有文件存储，标准化文献与独立原始元数据保存在数据库。
- 新增或删除一个索引只处理受影响来源，不全量重排已有文献。
- 导入、去重、AI 结果和人工审阅均绑定文献集修订，失败或并发冲突不会发布半套数据。
- 去重组、组成员、AI 待筛、人工审阅，以及质量评价的上传/方法选择/结果审核均使用服务端分页。
- AI 评价进度只展示实际进入评价流程的记录；批量确认只处理已有评价结果。
- XLSX、RIS、XML 导出共用有界数据库迭代器，不在内存中装载全项目结果。
- 上传文件数、字节数、总篇数、字段长度、压缩包和危险 XML 均有配置化限制与稳定错误码。

## 阶段 12 本地容量结果

可机读报告：`docs/benchmarks/screening-capacity-local-2026-09-29.json`。

基准环境为 10 核 Apple Silicon、Python 3.12.7、MySQL 8.0.32。以下数字只用于验证复杂度和同环境回归，不是生产服务器承诺：

| 项目 | 本地结果 |
| --- | ---: |
| 真实 RIS 流式解析 | 100,000 条 / 0.6418 秒 |
| 文献与原始元数据批量写入 | 100,000 条 / 20.9866 秒 |
| 数据库去重 | 100,000 条 / 5.3120 秒 |
| 筛选结果批量写入 | 99,001 条 / 8.5717 秒 |
| XLSX + RIS + XML 单遍导出 | 99,001 条 / 17.7512 秒 |
| 全流程进程峰值 RSS | 150.86 MiB |
| 五张核心表数据与索引估算 | 约 132.05 MiB |

查询复杂度证据：

- AI 输入首/末页：10/9 条 SQL，响应约 4.7 KiB。
- 去重组首/末页：9/8 条 SQL，响应约 6 KiB。
- 人工审阅首/末页：11/10 条 SQL，响应限于单页。
- 人工审阅统计：8 条 SQL，不读取结果文件。

边界自动化覆盖 100/101 个文件、50 MiB 单文件、200 MiB 请求、100,000/100,001 篇、字段长度、DTD/实体和 DOCX 路径穿越。解析取消、修订冲突、重复投递、AI 重试与计费幂等由对应领域测试覆盖。

## 上线前必须完成

以下工作必须在真实测试/生产同构服务器执行，不能用开发机基准替代：

1. 记录 CPU、内存、磁盘类型与剩余空间、MySQL/Redis 版本、Web/Worker 数量和 Celery 并发。
2. 使用脱敏真实索引重跑 1,000、25,000、50,000、100,000 篇，至少覆盖 RIS、NBIB、内部 XML、EndNote XML 和 Elsevier/Embase XML。
3. 验证同用户、同项目、跨项目并发导入；确认项目锁、用户限流和队列隔离符合配置。
4. 在任务运行时分别终止 Worker、短暂停止 MySQL/Redis、发送取消、重复投递同一任务，确认恢复后无半发布数据、重复结果或重复扣费。
5. 下载并校验 10 万篇项目的 XLSX、RIS、XML；检查行数、最终决定、人工覆盖、中文字段和文件大小。
6. 对数据库与私有文件存储执行一次完整备份和恢复，在恢复环境跑小样本全流程。
7. 观察慢查询、数据库连接数、Worker 峰值 RSS、队列长度、临时目录和私有存储增长；据此确定生产超时、并发和告警阈值。

任一项出现数据不一致、内存失控、无法恢复或重复扣费，都应阻止正式开放。

## 重复执行命令

```bash
# 自动化边界与领域回归
python manage.py test core.tests.test_screening_capacity_boundaries --keepdb

# 写入型容量测试；仅在确认可清理的测试数据库执行
python manage.py benchmark_screening_capacity \
  --references 100000 \
  --batch-size 1000 \
  --duplicate-every 100 \
  --execute \
  --output docs/benchmarks/screening-capacity-server.json
```

容量命令默认在结束时删除隔离测试用户和项目；加 `--keep-data` 才会保留。命令会对五张核心表执行 `ANALYZE TABLE` 以刷新空间估算，因此应安排在测试窗口，不要在生产业务高峰执行。
