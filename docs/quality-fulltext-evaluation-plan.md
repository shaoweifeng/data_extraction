## 1. 当前问题

当前链路存在两个相互独立的截断：

1. PDF 原文件可以完整上传，但文本提取默认只处理前 20 页。
2. 已提取文本进入 AI 评价时只取开头 8,000 个字符。

对英文医学论文而言，8,000 字符通常只覆盖约 2～4 页，容易遗漏方法、盲法、失访、统计分析、结果和附录。直接把 200,000 字符全部发送给模型也不合适，会显著增加上下文成本，并让模型难以准确定位证据。

当前方法体系还有以下扩展问题：

- `AI_SUPPORTED_METHODS` 手工限定为 QUADAS-2 和 NOS。
- 方法配置只有领域、问题和选项，缺少证据检索配置。
- 通用执行器一次性把所有问题和固定长度正文发送给模型。
- `evidence_page` 由模型自由生成，缺少系统可验证的页码来源。
- RoB 2、ROBINS-I、AMSTAR 2 尚未配置完整信号问题和汇总规则。

## 2. 目标架构

```text
私有 PDF
  → 安全校验和病毒扫描
  → 遍历全部页面提取文本
  → 保存页码、章节和截断状态
  → 生成带页码的文本块
  → 根据评价方法和信号问题检索证据
  → 按评价领域组成证据包
  → 单模型或多模型使用同一证据包评价
  → 校验证据引用和可选答案
  → 保存判断、原文、页码、块 ID 和版本
  → 人工审核及方法专属汇总
```

设计原则：

1. PDF 继续存放在私有文件存储，不把二进制全文写入数据库。
2. 去除“只提取前 20 页”，但保留 PDF 最大页数、文件大小、总提取字符数和任务超时等安全限制。
3. 不把整篇长文直接塞给模型；先完整提取，再检索与问题相关的证据。
4. 同一篇文献的多个模型必须使用完全相同的证据包。
5. 检索、Prompt、方法配置和聚合规则均记录版本，历史结果可以复算和解释。
6. 方法差异放在配置和聚合策略中，PDF 处理、检索、模型调用、计费和审计保持通用。
7. 首版使用本地确定性检索，不引入向量数据库或外部 Embedding 服务。

## 3. 数据设计

### 3.1 全文资产

在现有 `QAFulltextAsset` 上增量增加：

| 字段 | 用途 |
|---|---|
| `extraction_version` | 标记文本提取算法版本 |
| `extracted_page_count` | 实际完成提取的页数 |
| `extraction_truncated` | 是否因字符上限而提前停止 |
| `truncated_at_page` | 截断发生的 PDF 页码 |
| `chunk_index_file` | 私有 JSONL 分块文件 |
| `chunk_index_sha256` | 校验分块文件一致性 |
| `chunk_count` | 文本块数量 |
| `chunking_version` | 分块算法版本 |

`extracted_text_file` 继续保留为私有派生文本，不改变 PDF 原文件。提取文本应带稳定分页标记；分块文件保存：

```json
{
  "chunk_id": "p0003-c001",
  "page_start": 3,
  "page_end": 4,
  "section": "methods",
  "char_start": 8120,
  "char_end": 13240,
  "text": "...",
  "sha256": "..."
}
```

分块正文保存在私有文件，不在数据库重复保存大段全文。当前评价只需要读取单篇文献，不需要跨文献全文查询，因此首版没有引入全文搜索服务的必要。

### 3.2 评价证据快照

为 `QASignalItem` 增加：

| 字段 | 用途 |
|---|---|
| `evidence_sources` | 使用的块 ID、页码、章节、摘要和哈希 |
| `retrieval_version` | 证据检索算法版本 |
| `prompt_version` | 评价 Prompt 版本 |
| `method_config_version` | 方法配置版本 |

`model_results` 中每个模型结果也保留对应的判断、理由和证据引用。系统只能接受来自本次证据包的页码和短引文；模型输出无法匹配原文时标记为需人工核验，不能伪造证据位置。

### 3.3 方法配置契约

每种方法统一提供：

```python
{
    "key": "QUADAS2",
    "name": "QUADAS-2",
    "config_version": "1.0",
    "ai_supported": True,
    "evaluation_strategy": "domain_batches",
    "domains": [...],
    "signal_items": [
        {
            "domain": "patient_selection",
            "signal_key": "ps_consecutive",
            "signal_question": "是否纳入连续或随机样本？",
            "signal_description": "...",
            "options": ["是", "否", "不清楚"],
            "retrieval": {
                "queries": ["consecutive enrollment", "random sample"],
                "preferred_sections": ["methods", "participants"],
                "max_chunks": 5
            },
            "evidence_required": True
        }
    ],
    "aggregation_policy": "quadas2_v1"
}
```

配置校验必须保证：

- 方法 key、领域 key 和信号问题 key 唯一；
- 每个信号问题属于已定义领域；
- 选项非空且与前端、聚合规则兼容；
- 启用 AI 的问题具有检索配置；
- 聚合策略存在并通过该方法的固定测试样例；
- 配置版本变化不会覆盖历史评价快照。

## 4. 分阶段实施计划

### 阶段 0：冻结基线和回归样本

目标：在改代码前保留可以比较的现状。

工作内容：

1. 从现有本地样本中选择至少 10 篇 PDF：
   - 短文；
   - 超过 20 页的长文；
   - 双栏英文论文；
   - 图表较多的论文；
   - 扫描件或无法提取文本的 PDF；
   - 具有明确页码证据的 QUADAS-2 和 NOS 文献。
2. 记录当前提取页数、字符数、AI Token、评价结果和证据页码。
3. 为至少 2 篇文献人工标注关键证据所在页，作为检索回归样本。
4. 保存当前质量评价单模型和双模型 Token 基线。

验收标准：

- 回归样本不会提交原始受版权保护 PDF；仅在本地测试目录使用。
- 记录可以比较改造前后的提取范围、证据命中率和 Token 消耗。

暂停点：完成基线后再进入阶段 1。

### 阶段 1：完整分页提取

目标：去除文本提取前 20 页限制，不改变现有 AI 评价行为。

工作内容：

1. 删除 `QA_PDF_TEXT_MAX_PAGES` 配置及 `.env.example` 中对应变量。
2. 文本提取遍历 PDF 全部页面，达到 `QA_PDF_TEXT_MAX_CHARS` 后停止。
3. 保留以下安全限制：
   - `QA_FULLTEXT_MAX_FILE_BYTES`；
   - `QA_FULLTEXT_MAX_TOTAL_BYTES`；
   - `QA_FULLTEXT_MAX_PAGES`；
   - `QA_PDF_TEXT_MAX_CHARS`；
   - 处理任务软、硬超时；
   - 病毒扫描和加密 PDF 拒绝逻辑。
4. 提取文本加入稳定页码分隔符，不能把页眉页脚误当成页码来源。
5. 保存实际提取页数、是否截断和截断页码。
6. 历史兼容读取逻辑同样取消 20 页限制。
7. 增加管理命令，仅对指定项目或资产重新提取，禁止无边界地一次重建全部数据。

测试重点：

- 21 页、100 页和超过字符上限的 PDF；
- 空白页、混合中英文、损坏、加密和扫描 PDF；
- 字符上限准确生效；
- 重复执行不产生孤儿文件；
- 项目删除继续级联清理派生文件。

验收标准：

- 超过 20 页的 PDF 能提取后续页面文本。
- 现有 AI 仍暂时使用前 8,000 字符，结果流程不回归。
- 无需修改前端即可完成本阶段。

暂停点：人工检查长文末页文本和截断状态后再进入阶段 2。

### 阶段 2：章节识别与确定性分块

目标：把完整提取文本转换为可检索、可追溯的证据单元。

工作内容：

1. 增加分块服务，不放入 `qa_eval.py` 单文件中。
2. 首版分块建议：
   - 每块目标约 1,500～2,500 Token；
   - 相邻块保留约 10% 重叠；
   - 尽量在段落和句子边界切分；
   - 绝不丢失页码映射。
3. 识别常见中英文章节标题：摘要、引言、方法、对象、干预、结果、讨论、结论、附录等。
4. 保存 JSONL 分块文件、文件哈希、块数和算法版本。
5. 分块属于可重建派生数据，失败不能影响 PDF 原文件和已提取文本。
6. 为旧资产提供按项目重建分块的管理命令。
7. 提供只读验收报告命令，不能要求验收人员直接查询数据库或解析内部文件：

```bash
python manage.py inspect_qa_fulltext --asset-id <全文资产ID> --output <报告目录>
```

命令应输出一个可读 Markdown/JSON 报告和脱敏文本预览，至少包含：PDF 页数、实际提取页数、字符数、是否截断、截断页码、提取与分块版本、文件哈希、块数，以及每个块的页码、章节、字符数和开头预览。报告不得复制整篇受版权保护全文。

测试重点：

- 跨页段落、单页多栏、无章节标题、超长段落；
- 同样输入产生完全相同的块 ID 和哈希；
- 块页码覆盖正确；
- 分块文件损坏时能够重新生成。

验收标准：

- 任意文本块都能反查 PDF 页码。
- 重新分块不会改变 PDF、评价结果或用户上传状态。
- 10 篇基线文献全部生成有效分块。

阶段 2 人工验收步骤：

1. 从基线样本中至少选择 5 篇：
   - 1 篇少于 20 页；
   - 2 篇明显超过 20 页；
   - 1 篇超过 200,000 字符或能够触发截断；
   - 1 篇包含空白页、双栏、图表或特殊排版。
2. 在原 PDF 的第 21 页以后各选择一句容易辨认、但不包含敏感个人信息的短语。
3. 运行只读验收报告命令，确认：
   - `page_count` 与 PDF 阅读器显示一致；
   - 非截断文献的 `extracted_page_count` 不再停在 20；
   - `extracted_text_chars` 不超过 200,000；
   - 截断文献的 `extraction_truncated` 和 `truncated_at_page` 正确；
   - 第 21 页以后选取的短语能在提取预览或对应文本块中检索到；
   - 报告中的 `page_start/page_end` 与 PDF 实际页码一致。
4. 抽查每篇至少 5 个块：第一个块、最后一个块、跨页块、方法章节块和结果章节块，检查：
   - 没有乱码或大段重复；
   - 句子没有在不合理位置大量截断；
   - 相邻块只有配置允许的少量重叠；
   - 章节标签基本合理，识别失败时使用 `unknown`，不能伪造章节；
   - 页眉页脚不会单独形成大量无意义块。
5. 对同一资产连续执行两次重新提取和分块，确认：
   - 提取文本哈希、分块哈希和块 ID 完全一致；
   - 数据库没有重复资产或重复块记录；
   - 私有存储没有新增无法关联的孤儿文件。
6. 删除一个专门用于验收的测试项目，确认 PDF、提取文本和分块文件按现有删除策略一起清理；正式项目不得用于删除测试。
7. 检查处理耗时和日志：普通论文应在现有软、硬超时内完成；失败日志不能包含整篇全文正文。

人工验收只检查“完整提取、分页、分块和可重建性”，不在阶段 2 判断 AI 评价是否正确，也不产生真实模型调用和积分扣费。

暂停点：抽查块边界、章节和页码后再进入阶段 3。

### 阶段 3：评价方法配置标准化

目标：让新增质量评价方法主要通过配置完成。

工作内容：

1. 定义并实现统一方法配置 Schema 和校验器。
2. 给 QUADAS-2、NOS 补充：
   - 配置版本；
   - 评价策略；
   - 每个问题的检索查询；
   - 优先章节；
   - 最大证据块数；
   - 方法专属聚合策略标识。
3. 用 `ai_supported` 和配置完整性替代散落的 `AI_SUPPORTED_METHODS` 手工集合。
4. NOS 的队列研究和病例对照研究必须分别选择正确的问题、领域和检索配置。
5. RoB 2、ROBINS-I、AMSTAR 2 暂不凭空补写题目；配置不完整时保持 AI 不可用，并向前端返回明确原因。
6. 增加配置检查测试和管理命令。

测试重点：

- 重复 key、无效领域、空选项、缺失检索配置应启动失败或测试失败；
- QUADAS-2、NOS 现有界面数据契约不变化；
- 配置不完整的方法不能误进入 AI 任务。

验收标准：

- 新增一个测试方法只需要新增配置和聚合策略，不修改全文和 AI 执行器。
- 当前 QUADAS-2、NOS 配置全部通过校验。

暂停点：确认方法配置内容后再进入阶段 4。

阶段 3 实施结果：

- 增加统一配置校验器，应用启动时校验方法 key、领域、问题、答案、检索配置、版本及聚合策略；
- AI 可用方法完全由已校验配置中的 `ai_supported` 推导，前后端不再维护手写支持集合；
- QUADAS-2 的 14 条、NOS 队列研究的 8 条和病例对照研究的 7 条信号问题均配置中英文检索词、优先章节及证据块上限；
- NOS 新增明确的研究设计字段，历史空值按队列研究兼容，新选择可区分“队列研究”和“病例对照研究”；
- RoB 2、ROBINS-I、AMSTAR 2 保持 AI 不可用，并由接口返回具体不可用原因；
- 聚合规则以 `quadas2_v1`、`nos_v1` 注册并通过固定样例测试；
- 增加只读配置检查命令：

```bash
python manage.py check_qa_method_configs
```

人工验收时，在“方法选择”界面确认 NOS 展示两个独立选项，并分别选择后刷新页面，选择结果应保持不变。选择病例对照研究后进入 AI 评价，生成的问题 key 应以 `cc_` 开头；队列研究应以 `cohort_` 开头。长文证据链路是否生效由 `QA_EVIDENCE_RETRIEVAL_ENABLED` 决定，关闭时仍走前 8,000 字符的兼容链路。

### 阶段 4：证据检索引擎

目标：针对每个信号问题，从完整全文中选择最相关证据。

工作内容：

1. 实现本地确定性检索：
   - 关键词和短语命中；
   - 中英文同义词；
   - 章节权重；
   - 问题描述相关词；
   - 邻近块扩展；
   - 去重和长度预算。
2. 首版不调用模型生成摘要、不使用外部 Embedding，避免额外成本和不可解释性。
3. 按领域合并多个问题的候选块，避免同一段正文重复发送多次。
4. 证据包包含：文献基础信息、摘要、领域问题、选中块、页码和块 ID。
5. 设置单领域证据字符预算，建议首版 15,000～30,000 字符，由配置控制。
6. 没有命中证据时执行一次扩大范围的回退检索；仍无证据则允许模型回答“不清楚”，不能把缺失视为“否”。
7. 保存检索得分和选中块快照，便于调试但不向普通用户展示内部算法分数。

测试重点：

- 人工标注证据是否进入 Top-N；
- 盲法、随机化、排除、失访、随访时间等常见问题；
- 同一输入检索结果稳定；
- Prompt 注入文本只能作为文献数据，不能改变评价规则；
- 不同用户和项目的全文块绝不能交叉读取。

验收标准：

- 基线标注证据 Top-5 命中率达到预定阈值，首版建议不低于 90%。
- 每个证据块都包含可验证页码和哈希。

暂停点：先人工查看检索结果，不调用真实模型；确认后进入阶段 5。

阶段 4 实施结果：

- 新增纯本地确定性检索服务，不调用模型、Embedding 或外部搜索服务；
- 支持中英文短语、英文词形和分隔变化、问题描述词、章节加权、邻块扩展及一次扩大范围回退；
- 按领域合并问题候选块，同一块只保留一次，并记录对应问题、检索得分、页码、块 ID 和正文哈希；
- 严格执行 `QA_EVIDENCE_MAX_CHARS_PER_DOMAIN` 和 `QA_EVIDENCE_MAX_CHUNKS_PER_SIGNAL`；
- 没有证据时保留空覆盖，不将“没找到”解释成否定证据；
- 读取分块时校验项目/文献归属、分块文件哈希、块数量和每块正文哈希；
- 同一输入生成相同排序和证据快照 SHA256；
- 49 页本地回归样本生成 4 个领域包、覆盖 14 条 QUADAS-2 问题，单领域未超过 24,000 字符；该结果仅证明流程覆盖，相关性仍需人工抽查；
- 新增只读检索验收命令：

```bash
python manage.py inspect_qa_evidence \
  --reference-id <质量评价文献ID> \
  --output /tmp/qa-evidence-check
```

可以重复指定 `--signal-key` 只检查特定问题，例如：

```bash
python manage.py inspect_qa_evidence \
  --reference-id 123 \
  --output /tmp/qa-evidence-check \
  --signal-key ps_consecutive \
  --signal-key ft_all_analyzed
```

报告只包含限长预览，不复制整篇全文，不调用真实模型，也不扣积分。人工验收至少应抽查盲法、连续/随机入组、不恰当排除、失访和随访时间各一条，确认 Top-5 中存在原 PDF 对应页证据。

### 阶段 5：通用评价编排器

目标：用证据包替换固定前 8,000 字符，并保持单模型、多模型和人工审核流程。

工作内容：

1. 将现有一次性评价改为按领域批次评价。
2. 同一领域的所有模型使用相同证据包、问题和 Prompt 版本。
3. Prompt 要求每个判断返回：
   - `signal_key`；
   - 合法选项中的 `judgment`；
   - 简短理由；
   - 原文短引文；
   - 引用的块 ID 和页码。
4. 服务端验证：
   - 信号问题属于当前方法；
   - 判断属于配置选项；
   - 块 ID 来自本次证据包；
   - 引文能够在对应块中找到或进行规范化匹配。
5. 部分领域失败时只重试失败领域，不删除其他成功结果。
6. 多模型汇总沿用现有一致、分歧、部分成功逻辑，但保存各模型证据。
7. 方法专属聚合通过策略注册表实现，禁止在通用执行器中堆叠方法名称判断。
8. 通过功能开关 `QA_EVIDENCE_RETRIEVAL_ENABLED` 灰度；关闭时仍可回到旧逻辑。

测试重点：

- QUADAS-2、NOS 单模型和双模型；
- 某领域失败重试；
- 非法选项、伪造页码、不存在块 ID；
- 任务停止、恢复、重复结算和幂等；
- 多领域 Token 正确累计，不能遗漏或重复扣费。

验收标准：

- AI 不再直接使用全文开头 8,000 字符。
- 长文后半部分证据能够参与判断。
- 原有人工确认、结果可视化和导出结果不回归。

暂停点：使用管理员影子运行至少 10 篇，不向普通用户扣费；确认后进入阶段 6。

阶段 5 实施结果：

- 启用开关后，已完成提取和分块的全文改为按领域评价，不再将全文开头 8,000 字符直接交给模型；
- 同一领域的所有模型复用完全相同的证据包和 Prompt，Prompt 版本为 `qa-evidence-prompt-v1`；
- 服务端校验信号问题 key、合法选项、块 ID、页码范围和原文引用，对可核验页码和哈希使用服务端派生值；
- 每个模型的判断、引用块、页码、正文哈希、检索版本、方法配置版本、Prompt 版本和证据快照哈希保存在 `QASignalItem.model_results`；
- 领域只有在所有信号问题至少获得一个有效模型结果后才原子落库，失败领域重试时不删除或重跑已成功领域；
- 停止信号在领域边界生效，恢复后仅补跑未完成领域；任务 Token 汇总覆盖所有实际模型调用，并以任务 ID 作为扣费幂等键；
- 开关默认仍为 `false`，未启用时保持旧评价链路，无新增数据库迁移。

本地自动验证已通过 378 项 Django 测试，其中阶段 5 证据评价与续跑定向测试 19 项，覆盖 QUADAS-2、NOS、单/双模型、非法返回、局部重试、停止恢复、Token 累计和重复结算幂等。

管理员影子验收时，在测试环境设置 `QA_EVIDENCE_RETRIEVAL_ENABLED=true`，重启 Django 和 Celery，然后用管理员账户对至少 10 篇已完成全文提取的 QUADAS-2/NOS 文献执行 AI 评价。需核对：后半部分证据确实被引用、引用页与 PDF 原页一致、单/双模型结果正常、失败后重试没有改写已成功领域、管理员仅留存用量审计而不扣积分。阶段 6 前端尚未实现，本步先通过 Django shell 查询 `QASignalItem.model_results` 核对结构化证据字段。

### 阶段 6：前端证据与审计展示

目标：让用户理解 AI 为什么这样判断，同时不暴露无关全文内容。

工作内容：

1. 结果审核界面显示证据页码、章节和短引文。
2. 支持展开查看相邻上下文，但限制长度并校验项目权限。
3. 双模型分歧时并排展示各模型判断和引用证据。
4. 显示“全文被字符上限截断”“仅摘要评价”“证据不足”等状态。
5. 管理员可以查看提取版本、分块版本、检索版本、Prompt 版本和 Token 用量。
6. 导出报告中的证据页码来自系统快照，不直接信任模型自由文本。

验收标准：

- 普通用户只能读取自己项目的证据片段。
- 删除项目或全文后，相关派生文件和证据访问同时失效。
- 界面不会一次渲染整篇全文。

暂停点：完成人工端到端验收后进入阶段 7。

阶段 6 实施结果：

- 结果审核按模型展示判断、短引文、服务端核验页码、章节、证据块和“证据不足”状态；
- 用户只能按已经落库的引用块展开“当前块 ±1 相邻块”，接口重新校验项目归属、引用关系和派生文件完整性，单块最多返回 2,400 字符，不提供整篇全文读取；
- 双模型证据分别展示，管理员额外看到 Prompt、检索、方法配置和证据快照版本；普通用户不会收到内部哈希、版本或校验错误；
- 页面展示全文提取截断状态；管理员审计接口展示提取/分块版本、页数、字符数、块数和最近 QA 任务用量；
- Excel 证据表使用服务端保存的块 ID、章节、页码边界和正文哈希，多模型结果按模型分别导出；
- 项目、文献或全文删除后，证据上下文接口无法再读取相应派生内容；
- 阶段 6 定向后端测试 19 项、前端测试 42 项及生产构建已通过。

### 阶段 7：积分重测与套餐校准

目标：重新计算长全文证据评价的真实成本。

工作内容：

1. 使用至少 30 篇、最好 100 篇不同长度和方法的全文执行单模型、双模型测试。
2. 记录每篇：
   - 提取页数和字符数；
   - 分块数；
   - 每领域证据字符数；
   - 每模型输入、输出和缓存 Token；
   - 重试次数；
   - 实际积分和供应商成本。
3. 分别计算 P50、P75、P90，不只看平均数。
4. 更新个人套餐积分文档中的“100 篇双模型质量评价”预算。
5. 新计费逻辑上线前先影子记录，不修改用户余额。

验收标准：

- 平台积分计算与供应商账单误差处于允许范围。
- Lite 额度可以覆盖定义的一个标准月度工作量及合理波动。
- 费率和积分调整只新增版本，不追溯扣除历史积分。

暂停点：需要确认新的套餐积分后再进入阶段 8。

阶段 7 当前实施结果：

- 新增费率版本 `ai-credit-v1`，按模型分别计算输入/输出成本和影子积分；旧公式仍是实际扣费依据，验证期不会改变用户余额；
- `TokenUsageLog` 新增分模型用量、费率版本、影子积分和估算人民币成本，管理员审计界面同步展示；
- 新增 `benchmark_qa_evidence`，默认只在本地完成提取、分块、证据检索和提示词估算，显式传入 `--live` 才会向外部模型发送证据并记录真实 Token、错误、积分和成本；
- 已使用 `meta_project/QA_input` 的 30 篇 PDF 完成本地基准，30/30 成功且无字符截断。页数 P50/P75/P90 为 5/7/9.1，全文字符数为 15,379/21,617/39,009，分块数为 6/7.75/11，单模型全领域提示词估算为 25,852/28,446/35,120 tokens；
- 可审计明细保存在 `docs/qa-evidence-benchmark-local.json`，报告不包含 PDF 正文；
- 真实双模型运行尚未执行：该操作会把检索证据发送给 DeepSeek/Qwen 并产生费用，必须在明确授权后运行。因此供应商账单误差、输出 Token、重试率和新版套餐额度仍属于上线门禁，不能用本地估算冒充真实结果。

本地基准命令：

```bash
python manage.py benchmark_qa_evidence \
  --input-dir meta_project/QA_input \
  --limit 30 \
  --method QUADAS2 \
  --output docs/qa-evidence-benchmark-local.json
```

获得测试文献外发和费用授权后，真实双模型基准命令为：

```bash
python manage.py benchmark_qa_evidence \
  --input-dir meta_project/QA_input \
  --limit 30 \
  --method QUADAS2 \
  --models deepseek-v4-flash qwen3-7-flash \
  --live \
  --output docs/qa-evidence-benchmark-live.json
```

### 阶段 8：存量重建与灰度上线

目标：安全迁移已有全文并逐步替换旧评价链路。

工作内容：

1. 数据库迁移只增加字段，不删除旧字段或历史评价。
2. 按项目分批重新提取和分块旧 PDF，支持：
   - `--project-id`；
   - `--asset-id`；
   - `--limit`；
   - `--resume`；
   - `--dry-run`。
3. 重建失败不影响旧结果，并输出可重试清单。
4. 先开放管理员，再开放少量测试用户，最后全量启用。
5. 观察失败率、处理耗时、证据命中、Token 和积分至少 7 天。
6. 稳定后移除旧的前 8,000 字符评价分支；原始历史结果继续只读保留。

验收标准：

- 存量 PDF 可重复、安全地重建派生数据。
- 灰度开关关闭时可以回退旧链路。
- 全量启用后没有跨项目数据泄露、重复扣费或结果丢失。

阶段 8 实施结果与上线门禁：

- `rebuild_qa_fulltext` 已支持 `--asset-id`、`--project-id`、`--limit`、`--dry-run`、`--resume` 和 JSON `--report`；可用 `--retry-report` 只重跑上一报告的失败资产；当前版本已完成的资产会在续跑时跳过；
- 新增双层灰度：总开关 `QA_EVIDENCE_RETRIEVAL_ENABLED`，以及 `disabled/admin/allowlist/all` 四档 `QA_EVIDENCE_ROLLOUT_MODE`。白名单支持用户 ID、用户名或邮箱；管理员始终可进入 admin/allowlist 灰度；
- 当前本地环境设为 `enabled + admin`，普通用户仍走旧兼容链路；
- 新增 `report_qa_evidence_rollout --days 7`，汇总 QA 任务失败率、文献状态、Token、旧积分、影子积分和估算成本；可通过 `--fail-on-threshold` 在失败率超限时返回失败；
- 数据库迁移仅增加影子计费字段，不删除旧数据。重建失败会保留上一次可用派生文件；
- 尚未完成的时间型门禁是“管理员→白名单→全量”真实灰度和至少 7 天观察。因此旧 8,000 字符兼容分支与 `QA_AI_MAX_CONTENT_CHARS` 仍保留，只有真实观察通过后才能删除。

建议上线顺序：

```text
1. migrate，并保持 QA_EVIDENCE_ROLLOUT_MODE=admin
2. 管理员真实基准与人工证据核验
3. QA_EVIDENCE_ROLLOUT_MODE=allowlist，配置测试用户并观察
4. 连续运行 report_qa_evidence_rollout --days 7
5. 指标通过后改为 all
6. 全量稳定后另行提交删除旧 8,000 字符分支
```

## 6. 不在首版范围

- 外部向量数据库；
- 付费 Embedding API；
- OCR 扫描 PDF 自动识别；
- 表格、图片和补充材料的多模态理解；
- 自动生成尚未确认的 RoB 2、ROBINS-I、AMSTAR 2 官方问题；
- 跨文献语义搜索；
- 用模型摘要替代原文证据。

扫描件仍应明确提示“无法提取文本”，后续可以单独设计 OCR 和多模态阶段，不能在本次改造中隐式扩大范围。

## 7. 推荐执行顺序

实际开发依次执行：

```text
阶段 0 基线
  → 阶段 1 完整提取
  → 阶段 2 分块
  → 阶段 3 方法配置
  → 阶段 4 证据检索
  → 阶段 5 AI 编排
  → 阶段 6 前端与审计
  → 阶段 7 积分重测
  → 阶段 8 灰度上线
```

第一轮建议只执行到阶段 2 后暂停。此时已经解决 20 页限制并建立可复用全文分块，但尚未改变线上 AI 判断和扣费行为，风险最小，也最适合先检查长文处理质量。
