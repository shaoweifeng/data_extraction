# 商业化实施路线图

> 状态：方向性方案，具体价格、支付渠道、退款和税务规则需要经营主体确认后实施。  
> 前置条件：完成 [注册、账户与生产上线手册](./account-production-readiness.md) 中的生产验收。

## 核心策略

首发建议采用“免费体验 + Pro 订阅 + 按量积分包”，机构客户使用年度合同、对公转账和按需 BYOK。不要使用个人微信收款码作为长期方案。

建议保留四个清晰入口：

| 产品 | 建议价格 | 说明 |
|---|---:|---|
| Free | ¥0 | 小额度体验、有限项目与并发 |
| 积分包 | ¥29 / ¥99 / ¥299 起 | 适合低频或单项目用户 |
| Pro | ¥99/月或 ¥999/年 | 功能权益、优先队列与月度积分 |
| 机构版 | ¥9,800/年起 | 合同、对公付款、培训和管理员报表 |

价格只是验证起点。正式定价前必须记录模型输入、输出、缓存、失败重试、文献数、供应商成本和积分收入，用至少 30 天真实数据校准。

## 阶段 1：小范围付费试点

预计 2～4 周。

- 确定经营主体、服务条款、退款和开票方式。
- 使用官方商家收款码或对公转账，不使用个人收款码。
- 管理员核对到账后发放一次性兑换码。
- 首期只售 ¥29 和 ¥99 积分包。
- 埋点实际模型成本、积分消耗和用户转化。
- 验证付费意愿、退款原因和客服工作量。

当前已有兑换码和积分流水能力，适合先做低成本试点。

## 阶段 2：正式自助支付

预计 4～8 周。

- 完成域名、备案或许可判断及支付商户申请。
- 接入微信支付 Native 和支付宝电脑网站支付。
- 实现商品、价格版本、订单、支付通知、退款和发票申请。
- 商户订单号及渠道交易号设置唯一约束。
- 回调先验签和留存必要报文，再通过事务锁与状态机入账。
- 重复或乱序回调不能重复发放权益。
- 定时主动查单、下载账单并执行差异对账。
- 将积分升级为批次账本，区分购买、订阅、赠送和补偿积分。
- 支持有效期、消费顺序、退款和反向记账。
- 上线 Free、积分包、Pro 月付/年付；首版手动续费。

订单建议状态：

```text
CREATED → PAYING → PAID → FULFILLED
                    ├→ PARTIALLY_REFUNDED
                    ├→ REFUNDED
                    └→ CLOSED
```

## 阶段 3：机构化

预计 2～3 个月，获得明确机构客户后启动。

- 组织、成员、角色和管理员权限。
- 席位数量与共享积分池。
- 机构用量、费用和审计报表。
- 合同、对公转账、采购材料和数电发票。
- 数据导出和机构级数据边界。
- BYOK，由客户承担模型调用费用，平台收取软件服务费。

这会改变用户、项目和积分归属模型，应作为独立架构项目，不与个人支付同时开发。

## 阶段 4：验证后扩张

没有固定工期，只由真实订单驱动：

- 私有化部署、SSO、API/OEM。
- 自动续费及更复杂的订阅状态机。
- 海外支付、多币种和国际税务。
- MFA、Passkey、完整账户状态机。
- 更复杂的风控、设备识别和运营后台。

每增加一种售卖模式，都先确认权益、退款、税务、数据边界和技术隔离能够闭环。

## 下一步决策

开始付费试点前需要明确：

1. 经营主体类型和所在地。
2. 主要客户是个人、实验室、医院还是企业。
3. 服务器、域名和备案主体。
4. 是否可以开具数电发票。
5. 实际使用的模型供应商及最新成本。
6. 积分是否过期、如何退款、赠送积分能否退款。
7. 首批愿意参与试点的用户数量和可接受价格。
