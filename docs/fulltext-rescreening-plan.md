# 文献全文复筛：基于 plan 分支的设计与实施计划

> 状态：阶段 0～10 的功能开发已完成；阶段 8～10 的交付、部署及人工验收清单见第 18 节。正式数据库迁移、生产 MySQL 并发验证和用户人工验收仍待执行；Prompt/准确率调优不在本轮范围内。
> 日期：2026-10-27。
> 基线：`plan` 的 `ea1bb64`；参考 `origin/swf/double_check` 的 `4bdc3ab`。
> 原则：参考交互和业务流程，重新对接当前架构，不整体合并参考分支；准确率、Prompt 调优及人工金标准另设专项。

## 1. 判断与范围

参考分支的方向合理：从初筛纳入结果进入全文复筛，获取 PDF、维护标准、取得 AI 建议，再人工确认并导出。它已经包含前后端 MVP，不是纯前端。

但它不能与最新 plan 完美直接适配：参考分支基于 `3e90f15`，缺少 plan 后续的清理调度、加购并发及运行时限额变化等改动；自身还有元数据缩水、状态混存、模拟结果兜底、全文硬截断和计费/并发接入不完整的问题。

目标是新增可实际使用的 `SCREEN_2` 工作流，并维持初筛、质量评价和套餐账本的既有行为。本期不做全平台文献主表合并、不强制迁移全部旧 QA 全文、不开发 OCR、不接入收费全文采购、不进行真实模型大批量基准测试。

## 2. 哪些设计可以复用

| 部分 | 判断 | 采用方式 |
|---|---|---|
| 六步流程 | 可用 | 上传/导入 → 全文获取与绑定 → 排除标准 → AI 全文复筛 → 人工审阅 → 结果导出 |
| 上传、绑定、审阅、导出布局 | 可用 | 复用视觉布局与交互，按现有组件边界接入 |
| PDF 阅读与证据页码跳转 | 可用 | 复用阅读器能力，地址改为鉴权接口，并处理无效页码 |
| Store 和进度逻辑 | 不直接复用 | 改为服务端分页、任务 ID 轮询和持久化步骤状态；删除生产 mock |
| 从初筛最终结果导入 | 规则可用 | 复用 plan 的 `iter_resolved_screening_records`，保存来源运行和完整书目快照 |
| 全文 resolver 链 | 思路可用 | 本地候选 → 开放来源候选 → 校验 → 确认/绑定；外部查找异步化并加网络边界 |
| 人工最终决定优先 | 可用 | AI 只是建议；人工确认决定导出和 QA 导入 |
| 复筛模型、接口和 Handler | 不直接搬 | 独立领域模块，接入 plan 的任务、资产、计费和并发边界 |
| 分支迁移 0048 | 不复用 | plan 已有 0048/0049，按实施时的最新叶子新增迁移，不覆盖已有迁移 |

“前端可以搬过来”指页面骨架和局部交互可以复用，不包括把它的全量数据 Store、mock、可跳步判断及旧 Workspace 文件整体覆盖到 plan。

## 3. 工作流与业务语义

### 3.1 输入与完成条件

- 支持初筛当前有效运行的最终纳入文献、单独上传题录、单独上传 PDF。后两种允许独立开展复筛，不强制先跑初筛。
- 初筛导入使用用户实际确认/最终解析的结论，不只读取 AI 原始判断；默认不导入排除和待定，用户另行上传的文献明确标注来源。
- 重复执行同一来源导入只追加未导入文献；切换初筛运行时先展示差异，不自动移除旧复筛数据或覆盖人工决定。
- 全文步骤允许“未获取全文”，不要求所有文献均成功绑定才能继续；但只有校验和提取成功的全文才允许 AI 处理。
- AI 是可跳过步骤，人工可直接阅读全文作决定；跳过本身必须持久化，不伪造 AI 已完成。
- 所有需进入最终结果的文献必须人工确认；`pending` 为待定，不等于已作出最终纳排判断。未解决待定可导出草稿，但不能把整个复筛标为最终完成。
- 未取得全文与按标准排除分开统计。人工可确认“全文未获取”，导出单列该状态，避免 PRISMA 中将未获取全文混为适格性排除。
- 最终结果为：纳入、按标准排除、全文未获取；草稿还允许未审阅/待定。按标准排除必须有排除理由。
- 当前修订下所有记录已最终确认后可完成审核；最终导出成功或明确跳过导出后按现有生命周期完成步骤，刷新后不能退回未完成。

### 3.2 三类状态必须分开

1. 文件状态：未绑定、上传中、校验中、提取中、可用、失败、被拒绝。
2. AI 状态：未开始、排队、运行、完成、部分模型失败、失败、停止、输入已变更。
3. 人工状态：未审阅、纳入、排除、待定、确认全文未获取；另标注是否需要重新确认。

模型失败、全文获取失败、证据不足不能自动变为“排除”；任何生产路径都禁止在无模型结果时生成模拟纳入。

## 4. 元数据与结果存储

### 4.1 参考分支的缺口

它主要保留标题、作者、整数年份、期刊、摘要、DOI 和 PMID；相对当前初筛会遗漏卷期页、日期、PMCID、ISBN/ISSN、关键词、语言、出版商、来源数据库、机构、地址、原始记录和自定义提取字段。

`source_ref_id` 为普通整数，没有完整来源运行约束；`source_xml` 仍以旧文件存储思路命名。只存当前 AI/人工决定的宽表，也无法可靠保留重跑历史。

### 4.2 推荐模型边界

| 模型/记录 | 职责 |
|---|---|
| `RescreenCorpus` | 项目复筛文献集、输入修订号和当前有效运行 |
| `RescreenImportBatch` / `RescreenImportFile` | 上传与初筛导入任务、诊断、原文件、配额和来源批次；初筛导入不伪造原文件 |
| `RescreenReference` | 稳定文献身份、完整标准书目字段、来源关系、当前修订与移除标记；不混入全部运行历史 |
| `RescreenReferenceRawMetadata` | 独立冷表，保存完整原始字段、格式、解析版本、大小及哈希；不随列表查询默认返回 |
| `RescreenCriteriaRevision` | 稳定标准 ID、排除标准文本、修订与操作者；运行引用不可变标准版本 |
| `RescreenFulltextBinding` | 文献与全文资产的当前绑定及绑定历史、确认人和来源信息 |
| `RescreenRun` / `RescreenRunItem` | 一次运行及固定输入集合；绑定题录快照、全文哈希、标准版本和模型配置 |
| `RescreenModelResult` | 每个运行条目、每个模型的决定、理由、证据、错误与用量关联；技术失败单独记录 |
| `RescreenReview` / 审阅事件 | 人工最终决定、理由、备注和对应输入/建议版本；每次修改可追溯 |
| `FulltextAsset` | 新流程使用的私有 PDF、提取文本、页码与分块索引及处理生命周期，见下一节 |
| 全文查找任务 / 导出任务 | 复用现有 Task；导出通过私有 RescreenExport 凭据保存产物与版本，不注册为公开媒体 DataFile，不在请求中同步批量下载或内存打包 |

实体命名在阶段 0 最后核定；职责、来源、版本与唯一性约束不得省略。模型置于新模块的 `models.py`，按项目现有 app 注册方式接入，不继续把所有业务模型堆到 `core/models.py`。

### 4.3 元数据完整性规则

- 通用标准字段对齐 `ScreeningReference` 的现有全集；标题和摘要保持 Text，不截成 500 字；年份保留字符串，原始日期不强制转整数。
- 初筛来源保存 `source_reference`、`source_screening_run`、来源结果/最终决定及输入修订快照；使用真实外键，源被移除时仍保留历史快照。
- 原始字段冷表复制形成复筛自身快照，不能只依赖初筛原始表继续存在。原文件可保留受控引用，但不能导出时才临时反查源文件重解析。
- 自定义提取字段连同字段定义和版本保存为来源数据，不当作新的 AI 复筛字段自动改写。
- 独立上传复用现有解析器、校验报告和规范化映射，但不向 `SCREEN_1` 的文献集写入；抽出纯转换函数，不重写各格式解析器。
- PDF 元数据仅用于填空或提示候选，不能覆盖已确认题录；“CNKI”“Microsoft Administrator”等 PDF 生成器信息不能直接当作者/标题。
- DOI/PMID/标题相近只产生重复或匹配候选，不默认等同同一篇，更不能以 DOI 唯一约束吞掉不同报告。
- 全文可对应多个题录，多个报告可属于同一研究；本期不自动合并“研究”与“报告”。
- 编辑题录、替换 PDF、改变标准或移除文献均增加输入修订。旧运行和人工历史不被覆盖；新输入下旧结论标为过期，重新确认后才能用于最终导出。
- 运行条目保存标准书目快照/哈希及原始元数据版本引用，防止历史导出读到更新后的当前字段。冷表版本不可原地覆盖。

### 4.4 唯一性与导入一致性

- 初筛导入以“项目 + 来源类型 + 来源初筛文献身份”幂等；来源运行另存快照。换运行后的决定变化作为差异交给用户处理，不隐式复制成两篇。
- 原始题录以“导入文件 + 记录序号”定位；文件内容哈希用于提示重复上传，不把相同 DOI 当去重主键。
- 运行结果以“运行条目 + 模型”唯一，人工决定以相应输入版本唯一；回调/重试使用幂等键。
- 项目行锁/输入修订检查保证导入、删除、启动任务不会交叉产生半套数据。大文件分批事务处理，失败批次不可作为可用输入；不要在一个事务内解析或下载全部文件。

## 5. PDF 与长全文：复用能力而非耦合 QA 文献

### 5.1 资产设计

- PDF 仍存文件，数据库保存资产身份、路径、大小、哈希、状态和版本；不把 PDF 二进制写进数据库。
- 新增项目级 `FulltextAsset` 供新复筛及其下游使用，不能为了复筛先创建虚假的 `QAReference`。
- 目录默认 `private_media/fulltext/projects/<project_id>/<asset_key UUID>/`，原始 PDF、提取文本和索引分开，文件名不直接使用文献长标题；已被 `/private_media/` 忽略规则覆盖。
- 同一项目内的新资产按文件哈希复用，业务绑定单独记录；跨用户/项目不泄露重复判断和文件权限。
- 从现有 QA 提取可复用的 PDF 签名/扫描、逐页提取、确定性分块、哈希和证据区间等纯能力，QA 保留原服务入口与默认行为；先用原 QA 回归样本验证提取结果不变。
- 现有 `QAFulltextAsset` 与 `QAReference` 为一对一，不能直接让复筛共享它并依赖 QA 行的生命周期。
- 新资产与旧 QA 上传资产并存；首版不迁移旧文件，不宣称已经实现两套历史资产的全局去重。此后从复筛导入的 QA 文献通过适配器引用新资产，避免重复保存同一 PDF。

### 5.2 QA 兼容适配必须完整

为 QAReference 新增可选的来源复筛身份、复筛运行/人工结果快照和共享全文资产关联。统一读取适配器优先识别新资产，否则沿用旧 `fulltext_asset/fulltext_file`。

必须逐项适配 QA 列表/序列化、PDF 下载与 Range 请求、全文预检、提取/分块读取、证据 V2、引文上下文、重新提取、报告和清理；不能只新增外键，却让引擎继续只读旧一对一资产。

同一 PDF 的原始文本和分块可复用，基于不同标准产生的证据选择、模型评价和人工结论不能复用。提取或分块版本不匹配时重新生成派生资产，不能以“已有文本”为由跳过兼容检查。

### 5.3 删除与配额

- 原始 PDF 只按物理资产计一次空间，文本、索引和导出文件分别计入；新资产接入 `user_storage_usage_bytes` 和 `user_storage_quota_guard`。
- 手动上传、在线获取、派生文本写入和导出全部受用户套餐存储配额约束。后台任务不能绕过限额。
- 删除/替换绑定只解除该业务引用；仍被复筛运行或 QA 使用的资产不可物理删除。项目整体删除走统一收集流程，数据库事务提交后再清理实体文件。
- 清理任务先查引用与保留策略；有活动任务或证据快照使用的文本/索引不能直接删除。复用已配置凌晨清理调度。
- 私有 PDF 仅经项目权限鉴权下载，不返回公共 MEDIA_URL、服务器绝对路径或带密钥的来源 URL。

## 6. 全文获取

- 保留 resolver 可插拔设计：用户已上传候选、Europe PMC、Unpaywall、OpenAlex 等作为候选来源。查找条件、返回标识、出处与许可信息保存；“开放来源”不等于可以省略单篇许可检查。
- 高置信同项目 DOI/PMID 匹配且无冲突可自动绑定；仅标题相近、元数据不一致时交给人工确认。
- 首版提供本地上传/绑定与手动外链兜底；外部查找属于独立异步能力，不阻塞使用本地全文的复筛。
- 批量查找返回 job/task ID，支持分页进度、取消和重试；不使用浏览器无限超时请求串行下载数千篇。
- 元数据请求与下载均限制次数、超时、响应大小、并发、重定向和目标地址。每次重定向重新校验公开 HTTP(S) 目标，拒绝本机、私网、链路本地与云元数据地址；不能只校验初始 URL。
- 每个用户/项目设置搜索任务和总下载字节预算；文件先进入有大小约束的临时区，再验证 PDF、扫描、核对配额并发布为资产，失败要回收临时文件。
- 不自动访问需登录/付费/验证码的页面，不实现绕过访问控制的下载。未配置某个 resolver 时明确跳过，不影响其他来源和手工上传。
- 对外部服务是否收费、凭据如何申请，在实施该 resolver 时核验其当前官方文档；本方案不把第三方服务假定为永久免费或无限调用。

## 7. AI 复筛策略与运行

### 7.1 输入和判断

- 不沿用前 40 页/32,000 字符硬截断，也不无限制拼接全文。先完整处理允许范围内的 PDF，记录覆盖情况；达到资源上限必须明示部分覆盖，不能叫“完整全文已评价”。
- 允许范围内的短全文在模型输入预算内可整体发送；长全文按排除标准检索方法、对象、干预/暴露、设计和结局等相关证据，保留页码与稳定区间 ID。
- 复用 QA 的分块/证据定位基础设施，不复用 QUADAS/NOS 等方法的判断语义，不把“偏倚风险”套到“纳入/排除”。
- 每个模型输出逐标准判断（满足/违反/不明确）、整体建议、理由及证据 ID；证据不足为待定。只有明确违反标准且证据可验证，才形成可靠的排除建议。
- 所有要求纳入的标准均有足够依据才能建议纳入；缺少证据、输入部分覆盖或结构解析失败不默认排除。
- 引文优先使用本地证据 ID，页码和原文由服务器解析，避免要求模型自由抄写后再做脆弱字符串匹配；不存在的 ID 必须拒绝。
- 每条结果保留证据覆盖和校验状态供审阅，普通用户看到简洁的建议与待确认提示；模型调用、Token、原始 Prompt 等后台审计遵循现有角色策略。

### 7.2 运行、重试与人工决定

- `RescreenRun` 固定输入修订、标准、模型列表、全文哈希、Prompt/协议版本和费率版本；新跑生成新运行，不能直接清空上一轮所有结果。
- 一次只处理选中且资产 ready 的文献；部分失败允许对失败项重试，已完成项不重复调用和收费。
- 续跑同一运行只适用于输入未变的未完成项；用户主动重新评价已完成项创建新运行/明确的新调用，不能拿重试名义重复消费或改写历史。
- 双模型均独立产生结果；一个失败不能伪装成“双模型一致”，两者分歧或有关键待定时进入人工确认。
- 人工决定不会被重跑覆盖。输入或建议改变时标注需重新确认；并发保存使用版本号，旧页面修改返回冲突而非覆盖新决定。
- 完成进度以运行条目/模型任务统计为准，分别展示待处理、运行、完成、失败、跳过；前端按 task ID 恢复轮询，页面刷新不能丢任务或自行判断成功。
- 停止、异常、重复 Celery 投递和超时沿用现有生命周期与检查点机制；技术失败和无用量请求不伪装成完成。

### 7.3 计费与并发

- 新增 `ai_rescreen` 计费功能标识，任务步骤统一命名 `rescreen_ai`，映射关系集中维护，不散落硬编码。
- 补齐当前 `create_step_task`、Celery 槽位申请/释放、`slots_for_task`、预占/失败释放及账单功能标签中的 AI 步骤识别。仅注册 Handler 不足以接入这些能力。
- 每个模型 Provider 逐调用用量走现有规范和正式费率；任务创建冻结费率版本，使用现有批次账本，不另建复筛积分余额。
- 预估基于实际证据包/全文长度、选择模型、预计调用次数和输出上限计算；不能套 3,700/60 Token 的初筛均值或 2 积分/篇。
- 启动前预占、结束结算、停止/失败释放未使用额度；估算不足时在下一个调用前受控补充预占，补充失败则暂停未执行部分并结清已产生费用。
- 重试次数和平台/用户承担规则复用当前计费制度，平台解析缺陷造成的重试不得转嫁用户。
- 共享套餐、并发包和管理员覆盖后的最终槽位；复筛、初筛、QA 跨项目合计不超上限。实际同时请求数与租约数一致。
- 运行中升级/到期，在安全批次/调用边界刷新租约；排空、维护和取消逻辑同样适用复筛。
- 本方案不调整模型费率或商品价额，不虚构复筛基准成本。日后若建议套餐/参考售价，必须同时列成本和测算假设；真实付费基准另获用户授权后执行。

## 8. 前端、导出及 QA 衔接

### 8.1 前端

- 在 `web/src/features/rescreening` 内按组件、API、Store/控制器组织；只向 Workspace 注入 SCREEN_2 容器，不覆盖已有初筛/QA/商城改动。
- 所有列表默认服务端每页 50 条，可选 20/50/100、最大 200，带页码跳转、搜索和过滤；统计使用服务端聚合，不依靠当前页数组长度。
- 列表返回轻量字段，详情再取完整书目/原始字段/模型证据；原始冷元数据不在每次轮询中加载。
- 增加与现有初筛一致的模型选择、倍率提示和动态积分预估；Prompt 编辑仅 admin/researcher 可访问，普通用户响应和 HTML 均不包含私有配置。
- 步骤完成状态、当前有效运行和待处理数以服务器为准；不能用 `maxReachedStep` 或“浏览过某页”当完成依据。
- 保留图例/长标题处理经验：长标题省略并可展开，PDF 阅读器、证据跳转和多模型结果不挤压布局。

### 8.2 导出

- 按全部、纳入、排除、全文未获取、待定/未审阅草稿选择范围；在同一个下载入口选择 Excel/XML/EndNote（RIS），不为格式重复列出多行商品式条目。
- 完整书目字段和自定义来源字段复用统一映射；加上最终决定、排除标准 ID/文本、审阅信息、全文获取和证据摘要。
- 标准格式容不下的原始字段，XML 使用明确扩展结构、Excel 用附加表；RIS 只输出合法标签，不伪称已无损覆盖未知字段。可下载原始元数据 JSON 附件保留完整信息，需包含字段映射说明。
- Excel 防公式注入、超长单元格有明示处理；XML 安全转义；ZIP 文件名净化、索引清单可追溯。导出范围和实际条目数必须可核验。
- 导出用运行/人工决定修订快照，异步生成、分批读取、写磁盘后下载；不将上万 PDF 压入 BytesIO。文件名简短，不拼接全部模型名。
- 最终导出与草稿导出状态区分；旧修订产物可留历史，但不能标记新修订已完成。

### 8.3 QA 导入

- 保留现有从初筛直接导入 QA 的入口；新增显式选择复筛来源，不因启用复筛全局改变所有 QA 用户的路径。
- 默认仅导入当前已最终确认的复筛纳入结果；项目复筛尚有待定时，可以明确选择“导入已确认纳入子集”，但不得将整个复筛标记完成。
- 保存来源文献、运行、人工决定修订和完整书目快照；PDF/文本经资产适配器引用，不只赋值旧 `fulltext_file`。
- 导入幂等、默认增量预览；重复导入不能执行 `_clear_quality_results` 清空已有评价。已有 QA 评价时，来源变化必须先展示差异和显式确认。
- QA 目前的展示字段可继续保留，完整元数据快照另存关联并用于后续导出，不能因 QAReference 没有某个列又把信息丢掉。

## 11. 验收主线与回归边界

1. **标准链路**：初筛已确认纳入 → 复筛导入 → 上传/绑定 PDF → 标准 → 双模型建议 → 人工决定 → 导出 → 纳入文献导入 QA。
2. **独立使用**：不跑初筛，直接上传题录/PDF → 手工复筛；AI 可跳过，原始元数据保持完整。
3. **缺失与故障**：无全文、扫描 PDF、无文本、模型无凭据/失败、证据无效、额度不足，不能得到伪造的纳入或排除结论。
4. **变更与重跑**：替换 PDF/修改标准/初筛来源变化/重复导入，不覆盖历史，需确认的旧结果不能继续冒充最终结果。
5. **大批量**：分页、服务器聚合、异步查找和导出，浏览器不持有全部文献；批次可取消、失败可重试。
6. **账户与资源**：项目隔离、私有下载、角色能力、套餐存储/积分/并发包、生效与到期、维护排空及引用安全清理。
7. **原功能**：旧初筛导入/导出、旧 QA 全文 V2、人工审核、报告、商城/兑换和凌晨清理均不退化。

实现复杂度为中高，主要工作在资产共享、版本快照和计费/并发接入，而不是六个前端页面。将这些基础纳入本轮设计，比先上线简化宽表、再补存储重构更可控。

## 12. 阶段 0 冻结的实现契约

### 12.1 模块、实体与状态

- 领域代码位于 `core/rescreening/`；共享资产模型/存储位于 `core/fulltext/`；纯书目映射位于 `core/bibliography.py`。仍使用现有 `core` app 的模型注册与迁移链。
- 工作流标识 `SCREEN_2`；现已接入后台步骤 `rescreen_import`、`rescreen_pdf`、`rescreen_fetch`、`rescreen_ai`。不复用 `parse`、`ai_screen` 或 `qa_eval` 的业务状态。
- 已落表的基础实体：`RescreenCorpus`、`RescreenImportBatch/File`、`RescreenReference`、`RescreenReferenceRawMetadata`、`RescreenCriteriaRevision`、`RescreenFulltextBinding`、`RescreenRun/RunItem/ModelResult`、`RescreenReview/ReviewEvent`、`FulltextAsset`、`QASourceBibliographySnapshot`。
- 全文上传、查找、AI 运行及 QA 资产读取适配现已接入；人工审阅和正式复筛→QA 导入仍分别属于阶段 7、9。旧 QA 可选关联默认 NULL，保持原路径兼容。
- 导入状态：`uploaded → importing → completed/failed`；运行中停止先进入 `cancelling`，由 Worker 确认后进入 `cancelled`；尚未领取的批次可直接取消。`ready` 为保留的活动状态。
- 只有批次 completed 且文献引入修订不大于 corpus 当前修订的记录可发布；列表再排除已移除记录。分块写入不是逐块发布，失败清除本次暂存文献，保留源文件和诊断供重试。
- **导入完成不等于全文复筛完成**。本阶段没有最终审阅/导出完成接口，不能据此解锁 QA 下游，也不会自动启动模型。

### 12.2 字段与来源

标准字段固定为：标题、摘要、作者、期刊、出版年、出版日期、DOI、PMID、PMCID、ISBN、ISSN、URL、文献类型、卷、期、页码、关键词、语言、出版社、数据库、机构、地址、原始记录标识。映射与初筛共用，不另设 RIS 专属窄表；额外字段进入独立冷元数据版本表。

初筛来源使用当前语料版本的已完成运行，并按现有最终决定规则读取，人工决定优先。只导入最终纳入记录，保留全部标准字段、完整原始字段、额外提取字段、源文献/结果/运行 ID、源文件名/哈希与来源指纹。

现有初筛运行未冻结历史字段定义，所以导入时保存当前 `field_extraction` 的 metadata，明确标注 `captured_from=stage_at_import`，不伪称是历史运行定义。其哈希也参与来源变动检测。

来源键为 `screening:<source_reference_id>` 或 `file:<import_file_id>:<source_position>`，项目内唯一。重复初筛导入仅追加新纳入记录；不自动恢复已移除记录、不覆盖既有文献。来源字段/原始字段/最终决定/字段定义变化会产生差异，当前拒绝自动覆盖，后续界面提供显式处理。

原始元数据按 `(reference, input_version)` 唯一，正常保存禁止原地改写；新版本采用新增行。热列表不联查完整原始 JSON。

### 12.3 私有资产与 QA 适配清单

默认复筛题录路径为 `private_media/rescreening/imports/project_<id>/batch_<id>/<随机名>.<后缀>`；共享全文路径为 `private_media/fulltext/projects/<project_id>/<asset_key UUID>/<随机名>.<后缀>`。二者均不提供公开 `.url()`，且已被现有 `.gitignore` 的 `/private_media/` 覆盖。

共享资产以项目和 sha256 唯一，绑定及运行引用受 RESTRICT 保护；QA 来源外键可置空，但独立冷快照保留来源信息。项目级联删除时收集新表，私有实体文件在数据库提交后删除，回滚不提前丢文件。

阶段 3、9 必须覆盖的旧 QA 直接读取点，不能遗漏：

| 位置 | 需要通过共享适配器覆盖的职责 |
|---|---|
| `quality/services/fulltext.py`、`quality/tasks.py` | 资产创建、预处理、重提取、保留策略 |
| `quality/executors/qa_eval.py` | ready 检查、资产查询、旧全文直读、证据模式输入 |
| `quality/services/evidence_retrieval.py` | 分块索引读取、资产哈希与版本 |
| `quality/services/evidence_context.py`、`quality/api/review_views.py` | 证据上下文、页码与原文定位 |
| `quality/api/common.py`、`quality/api/reference_views.py` | 列表序列化、PDF 下载、上传/替换/重试 |
| `quality/signals.py`、`services/storage_quota_service.py` | 引用保护、生命周期、物理字节计量 |

适配器契约：共享资产存在时返回共享资产，否则回退旧 `QAFulltextAsset/fulltext_file`；统一提供私有原文件、提取文本、分块索引、状态/覆盖范围、版本和哈希。阶段 0～2 **没有切换上述 QA 读取路径**，避免半接入状态。

### 12.4 资源与后续 AI 预算边界

题录直接复用现有 `SCREENING_IMPORT_*` 的配置对象：100 文件、50 MiB/文件、200 MiB/请求、100,000 条/复筛项目文献集。作者数、字段长度、单记录文本/原始 JSON、数据库批量大小、处理检查间隔、账户导入速率/并发与失败保留天数也沿用，不添加另一套不一致的默认值。同一复筛项目固定串行发布，不因初筛每项目并发参数调大而允许并发导入。初筛与复筛各自维护语料上限，物理存储配额按账户合计。

阶段 3 的全文提取/分块默认对齐现有 QA 的 1,000 页、200,000 字符、目标 2,000 token 分块和 200 token 重叠；触顶必须保留“覆盖不完整”信息。它们是资源保护，不代表 AI 可以只看开头就当作完整复筛。

阶段 5 已接线的默认预算：短全文阈值 24,000 字符；长文使用证据分块而非截取前 N 字符；每标准证据上限 12,000 字符、每次请求证据正文总预算 64,000 字符、输出上限 4,096 token、每文献每模型累计调用上限 12 次，标准条目最多 50 条。独立 `RESCREEN_*` 配置已写入 `.env.example`，详见第 16 节。每批最多 8 条标准；最终 Prompt 连同证据 ID、页码及输出还受保守 token 预算约束，不静默截断、不伪造排除。

调用预算和长文选择不作为“准确率保证”；Prompt 与准确率调优仍后置。阶段 6 已接入冻结费率预占、逐调用用量与结算，导入本身不计模型积分。

### 15.1 私有全文与兼容边界

- 上传 PDF 形成共享 `FulltextAsset`，相同项目相同 SHA256 复用一份物理文件；不创建假的初筛记录或 QA 记录。独立 PDF 复筛由 `create_references=true` 明确创建题录与待处理绑定；重复上传不会自动恢复已移除的同源题录，响应使用 removed 标明，避免隐式恢复用户已删除的输入。
- 上传、处理、查找分别采用 `rescreen_pdf`、`rescreen_fetch` 任务类型，接入现有 Task/Celery/日志。PDF 使用现有 120/150 秒软/硬超时；查找默认 900/930 秒；重复投递不重复领取处理租约。
- 签名/哈希、扫描器、逐页提取、分块、Storage 物化已抽至 `core/fulltext/`。QA 原路径保留兼容导出，提取和分块协议版本不变；新旧资产对同一 PDF 产生相同文本/分块哈希。
- PDF 原文件在处理时再次校验上传哈希；损坏、加密、页数超限和扫描拒绝不会成为可用全文。无文本扫描 PDF 可以阅读，但不会标记为 AI-ready；不提供 OCR。
- 页面与字符预算沿用 QA 安全配置。超过字符预算明确保留截断页与覆盖不完整状态，`ai_ready=false`，不把截断文本冒充完整全文。PDF 自带 CNKI/制作软件作者等元数据仅保存诊断，不覆盖已确认题录。
- 已有题录须等待资产 ready 后显式绑定；绑定、替换、解绑均检查输入版本，更新文献/文献集修订，复制冷元数据版本并清除当前审核/运行指针，保留旧历史。
- 被历史绑定、运行或 QA 引用的全文不允许直接删除或原地重建证据。未引用资产可以显式重建。该保守策略意味着历史绑定的旧 PDF 仍占用存储配额；项目整体删除才能回收其级联文件。

### 15.2 查找、候选与网络安全

- 本地查找只扫描同项目的 ready 资产，按 DOI/PMID 或规范化文件题名产生有界候选。只有单一且无标识冲突的高置信候选，在显式 `auto_bind=true` 时才会自动绑定；标题命中、多候选、标识冲突都留待人工确认。
- 首版实现 Europe PMC 和 Unpaywall 元数据 resolver；只查询明确的 DOI/PMID/PMCID，不上传 PDF 给第三方。OpenAlex 等是未来扩展，不是当前已接入来源。
- 外部查询默认关闭。Unpaywall 联系邮箱缺失时明确记录跳过原因；不影响本地查找、手动上传或 Europe PMC。许可缺失/不在允许列表时仅保留候选链接，不自动下载；默认自动下载许可为 cc0/cc-by/cc-by-sa，下载来源与许可保留在后台。
- 依据官方说明接入：[Europe PMC API](https://europepmc.org/RestfulWebService)、[Europe PMC 许可说明](https://europepmc.org/help)、[Unpaywall REST API](https://data.unpaywall.org/products/api)、[Unpaywall 字段说明](https://unpaywall.org/data-format)。服务级访问许可不替代单篇许可；不抓取付费/需认证页面，不绕过登录或验证码。
- 每次 DNS 解析检查所有返回地址，拒绝私网、环回、链路本地、保留地址和混合公网/私网结果；连接固定到已检查的 IP，HTTPS 仍用原域名 SNI 和默认证书校验。每跳重定向重新校验，不使用系统代理、Cookie 或来源认证头。
- 限制 HTTP 请求次数、DNS/连接/读取/总超时、重定向、JSON/PDF 大小及任务总接收正文预算。失败流已接收的正文也计入；只接收非压缩响应，PDF 同时核对 MIME/签名/完整性并走扫描与提取。
- 一个账户同时一个查找任务，默认每分钟 3 个任务、每任务最多 50 篇/100 请求/200 MiB，按任务创建日累计的账户每日接收正文预算默认 512 MiB。下载完成后仍须通过实际存储配额检查。
- 下载先进入无持久文件名的临时区，异常/中止自动回收；后台持久化后仍做 PDF 核验。远端元数据匹配不等于正文必然正确，自动绑定还要检查 PDF 内 DOI/PMID；否则作为候选供人工确认。
- 停止运行中任务先进入 cancelling，Worker 在网络分块/文件/页面边界确认；停止不撤销已经完成的合法绑定。重试创建新任务，只选择失败/未完成/未找到条目，保留原任务历史。

### 16.1 运行和证据协议

实现位置：`core/rescreening/services/ai_protocol.py`（纯证据与校验）、`ai_runs.py`（运行命令）、`ai_execution.py`（Worker）、`ai_billing.py`（计费适配）。共享 AI 步骤/计费功能映射集中在 `core/ai/features.py`。不把复筛语义写进 QA 方法或初筛 Provider。

- 新建运行冻结题录/原始元数据版本、语料修订、排除标准修订、资产及派生哈希、模型身份与非密钥请求配置、证据包、Prompt 正文/协议版本和完整费率快照；API Key 不写入快照。
- 仅处理用户明确选择的、已发布且当前绑定全文完整 ready 的文献；无全文、扫描件无可引用文本、提取截断、资产校验失败或分块版本不兼容时明确拒绝，不用摘要偷偷替代完整全文。
- 短文在预算允许时发送全部可引用原文；长文对全文所有区间按标准词项和方法/对象/结果章节选择证据，不是取开头 N 字符。证据超预算时按完整区间调整，并明确标注 `strategy=retrieved`、所选/总区间数。词项检索是功能首版，并不代表召回率或准确率已优化。
- 每批最多 8 条标准，50 条最多需要 7 批/模型；每篇每模型累计最多 12 次请求，包括技术失败、未知请求和用户重试。批次和单模型结果都可持久化续跑。不能因后一个批次失败而重发已成功的前面批次。
- 每条标准必须返回 `satisfied`（明确不触发排除）、`violated`（明确触发）或 `unclear`（不明确）及证据 ID。服务器检查标准数量/重复编号/合法值/证据 ID/理由长度，从本地冻结证据解析原文和页码，不依赖自由抄写引文。
- 无证据的确定判断降为不明确；服务器根据逐标准结果计算整体建议：有证据的违反→排除，全部有证据且不触发排除→纳入，其他→待定。错误 JSON、未知证据、遗漏标准不生成成功结果。
- 模型独立保存；只有所有选定模型均成功且建议一致时形成明确共识，单模型失败、分歧或关键待定时保留待定，等待人工。AI 不写入或覆盖人工审核记录。
- `RescreenCall` 是每次真实请求的日志：请求哈希、标准组、尝试序号、任务身份、响应、用量、解析结果和错误。先记调用、先保存用量，再解析结果，避免坏 JSON 吞掉真实费用。
- 未配置模型凭据直接拒绝，生产没有 mock 或随机建议。单次网络失败不自动请求重试；重试必须由明确操作触发。

运行状态：`pending → running → completed/partial/failed/paused`；运行中取消先 `cancelling`，当前请求返回并结算后才可续跑。计费故障为 `settlement_pending`，保留预占且阻止输入变更或新一轮运行，恢复结算后再操作。

`partial` 表示部分模型/文献成功，并不伪装为全成功；对应后台 Task 可以成功完成“本轮处理”，调用方必须读取运行状态和条目聚合。AI 运行完成不代表人工最终复筛完成，也不在本阶段解锁 QA 正式导入。

进程硬中断时，已保存调用结果继续有效；尚未收到响应/用量的请求标为未知。重试返回 `unknown_call_requires_ack`，需显式 `acknowledge_unknown=true`，提示可能再次产生供应商费用。无法凭空恢复供应商未返回的准确用量，也不会按估算值假装真实扣费。旧进程迟到响应只记平台承担的审计，不发布到新一代运行或追扣用户。

### 16.2 积分与并发

- 计费功能为 `ai_rescreen`，任务类型为 `rescreen_ai`。普通用户使用既有批次账本，必须开启 `MODEL_WEIGHTED_BILLING_ENABLED`、`CREDIT_BATCH_LEDGER_ENABLED`、`BILLING_RESERVATION_ENABLED`；管理员仍无限积分，但保留真实费率的用量审计。
- 预估以本次冻结的真实证据请求长度、分批数量、模型及输出上限计算，不套用初筛/QA 的均值或固定 2 积分。为避免本地分词低估，首版使用 UTF-8 字节数加安全余量作为保守输入 token 上界，因此预占可能明显高于最终实际消费；差额结束时释放。这不是新的售价、模型费率或成本基准。
- 启动前预占，余额不足回滚整轮创建；每个调用前将已有真实用量加上下一个请求上界重算，必要时原子补占。补占不足暂停未执行部分，结清已发生的已知用量，不让余额变负。
- 按任务逐调用累计并结算一次；缓存、厂商模型标识、上下文区间、请求 ID、重试序号、费用承担方进入原有审计。每次续跑创建新 Task/预占，只结算新调用，保留原运行/结果和旧任务账单。
- 非法结构/证据等失败响应保留真实用量但由平台承担；其后针对该失败批次的协议重试也标记平台承担。明确的新一轮评价仍按用户任务计费。
- 费率变更不影响已启动运行：预估和实际结算都使用该运行冻结的费率内容与版本。结算可重复调用，不重复扣费或生成重复账单；故障不直接释放已发生消费对应的预占。
- 原有预占过期命令不会把活动复筛任务的预占当无用资金释放；已结束复筛先核对真实调用日志再结算。
- 复筛每任务串行请求，申请 **1 个**共享槽位；与初筛池、QA 跨项目累计占用同一用户/全局池。每次请求前重新解析套餐/并发包权益并刷新租约，升级、到期在安全边界生效，不中断已发出的请求。
- 复筛对 Redis 不可用采用拒绝调用，避免降级绕过并发限制；不改变既有初筛/QA 的降级策略。租约覆盖硬超时，避免长请求中途自然过期失去占槽。
- 已接入排空拒绝新任务、维护暂停/恢复、人工停止、Worker 异常/超时、服务重启后中断任务恢复。输入或标准已变化时禁止续跑旧运行，应显式创建新运行。

## 18. 阶段 8～10：导出、QA 衔接与交付（2026-10-27）

### 18.1 阶段 8：实际交付与完成规则

在复筛第六步统一选择“范围 / 格式 / 草稿或最终”，不重复铺设同一结果的多行格式按钮：

- 范围：所有文献、纳入文献、排除文献、全文未获取文献、待定/未审阅草稿。可选择范围内起始序号和条数分批导出（SQL 截取），大 PDF 包可自行分段，不必提高单文件上限。
- 格式：Excel、结构化 XML、EndNote/RIS、完整原始元数据 JSONL、全文 PDF ZIP。
- 书目常见字段全部取自数据库当前规范字段；厂商额外字段、来源提取字段/定义、原始元数据、各模型结果及人工理由/备注一并保存在完整记录中。私有 Prompt、Token/内部计费日志不导出。
- Excel 使用只写模式，普通字段展示在主表，完整记录放在元数据表；长内容按文献 ID、字段名、part 分段，不静默截断；超大元数据表自动分表。字符串强制文本，防止公式注入。XML 使用与初筛一致的书目标签并附完整 JSON；RIS 使用标准标签，并在记录结束前附完整记录的 Notes。
- PDF 包异步、分块读写，不把所有 PDF 读进内存；使用内部文献 ID 命名，附带 title、文件名及 SHA-256 清单；缺少 PDF 的文献也保留清单项。文件内容校验不通过则整包失败，不发布部分产物。
- 每项目同时一个导出任务；支持刷新恢复、停止、分页查看及重新生成。失败后用新请求重新生成，不复用已取消的 Worker。幂等重试返回同一凭据。
- 生成时冻结独立快照明细；生成期间继续改审阅不会混入文件。列表清楚区分当前/历史版本。文件名只有范围、模式与任务 ID，不拼接模型全名。
- 只有“人工最终判断全部有效”且“当前指纹的最终 Excel/XML/RIS 成功生成”或用户明确确认“跳过本版本导出”，第六步才算完成。跳过有独立审计凭据，不能冒充已生成文件。草稿、PDF 包、JSONL 附件、单纯打开页面、失败/取消任务均不完成。完成凭据持久化，刷新不回退；文献输入、标准、AI 建议或人工确认变化后旧凭据不冒充当前结果。
- 文件与导出快照占用计入账户配额；Worker 发布时在 owner → project 锁内再验配额。临时目录、Excel 临时 XML、失败半成品会清理。默认 7 天清理文件和明细，但保留小型完成凭据；用户也可主动“清理生成文件”释放配额，不删除原始文献、PDF 或审核记录。

新增模型：RescreenExport / RescreenExportItem。快照按 500 行批次读取/落库；状态指纹使用 SQL 聚合与单调审核事件 ID，不在每次轮询读取十万篇原始 JSON。导出生命周期归属 services/exports.py，格式实现独立放在 services/export_rendering.py。

### 18.2 阶段 9：复筛 → 质量评价

复筛第六步与原 QA“从文献复筛导入”均接入相同的预览确认服务：

1. 仅读取当前有效且人工决定为“纳入”的文献；AI 建议、待定及过期人工结论不会自动导入。
2. 预览显示新增、已存在、来源已变更、不再纳入/已移除的数量与前 100 条差异；确认 Token 绑定复筛与现有 QA 来源状态，变化后返回 409 要求重新预览。
3. 按 source_rescreen_reference 增量创建 QAReference，有数据库唯一约束及 owner → project 锁；重复导入不重复创建。
4. QA 使用已有 shared_fulltext_asset，不复制 PDF、不重复计算文件配额，导入本身不调用模型、不收模型积分；无可用 PDF 的人工纳入文献保留为待获取。
5. QASourceBibliographySnapshot 保存完整书目、原始/额外元数据和来源审核快照，避免 QA 展示字段的长度上限使来源信息丢失。具体 QA 方法/模型由用户后续选择。
6. 已有 QA 文献、方法、AI/人工评价、图表不清空。源版本变化或不再纳入时必须明确确认“保留已有快照/成果，仅追加新文献”，不会偷偷覆盖或删除。
7. QA 存在活动评价任务时拒绝导入。旧 QA 的直接上传、初筛导入、证据 V2、鉴权下载、图表和报告路径保持原语义。注意：**从初筛导入仍是原来的清空重建流程**，界面继续明确警告；只有复筛来源采用新增量规则。

QA Excel 增加“复筛来源元数据”附表，按文献 ID/part 保存完整来源 JSON，保留完整书目、厂商字段及审核快照；所有字符串都作为文字而非公式保存。旧 QA 无复筛来源时不增加该附表。既有 QA 报告仍为内存工作簿，新来源附表设 32 MiB（且不超过复筛导出上限）的安全预算，超限返回明确 413 而不是截断；大规模原始数据可通过复筛分批 JSONL 导出。QA 报告流式重构可另行规划。

既有 QA facade 仍为部分评价/导航能力保留全量文献缓存，本轮没有把整个 QA 前端 Store 重写成纯分页；复筛模块及 QA 列表自身使用服务端分页。大规模 QA Store 优化可单独规划，不能把本轮说成已消除所有 QA 全量加载。
