# 部署后前端集成测试方案

> 适用范围：当前 `data_extraction` 平台部署版本  
> 测试类型：部署后端到端集成测试、异常场景测试、多人并发与项目隔离测试  
> 文档用途：按模块分配测试人员、记录执行结果、作为上线验收依据  
> 最近更新：2026-09-12

## 1. 测试目标

本方案验证部署后的真实前端、Django API、数据库、Redis、Celery、文件存储及 AI 服务能够协同工作，重点确认：

- 所有已开放界面可进入、可操作、状态展示正确；
- 数据在刷新、重新登录、切换项目后仍保持一致；
- 异步任务能启动、更新、暂停、恢复、取消和正确结束；
- 不同用户、项目、浏览器标签页之间的数据和进度严格隔离；
- 慢网络、断网、重复点击、异常文件、额度不足等场景不会造成错误数据或界面假死；
- 下载文件内容、编码、列结构和文件名正确；
- 管理员权限及维护状态符合产品约定。

本轮以浏览器可见行为为主。发现问题时，可以用浏览器 Network、Console、服务日志和数据库只读查询辅助定位，但不能用“接口调用成功”代替前端验收。

## 2. 当前产品边界

### 2.1 完整测试的模块

- 登录、注册、退出及会话恢复；
- 项目创建、进入、切换和删除；
- 文献初筛全流程：索引导入、解析、去重、纳排标准、自定义字段、AI 初筛、人工审阅、结果导出；
- 文献质量评价全流程：从初筛导入/PDF 上传、方法选择、AI 评价、人工确认、结果可视化、报告导出；
- 个人中心：余额、并发档位、兑换码、交易流水；
- 全局问题反馈；
- 管理员运维页面及维护状态；
- 全局导航、任务日志、权限隔离、异常恢复和兼容性。

### 2.2 仅验证占位状态的模块

以下入口当前应稳定展示“正在建设中/Coming Soon”，不得误导用户已经可用，也不应因点击产生后台任务：

- 文献检索；
- 文献复筛；
- 数据提取；
- Meta 分析；
- 质量评价中的题录文件导入；
- 质量评价中的手工“绑定全文”。

除非占位表现与上述约定不符，否则不能把“功能尚未开放”登记为缺陷。

## 3. 测试环境与准入条件

### 3.1 环境要求

| 项目 | 要求 |
|---|---|
| 部署方式 | 使用待上线代码、迁移和已提交的 `web/dist`；服务器使用 `./start.sh --no-build` |
| 浏览器 | Chrome 当前稳定版为主；Edge、Safari、Firefox 各完成一轮核心冒烟 |
| 屏幕 | 1920×1080、1366×768；另测 390×844 的窄屏基本可用性 |
| 服务 | Django/Gunicorn、Celery、Redis、数据库、文件存储均为真实部署组件 |
| AI 模型 | 至少配置两个可用模型；另准备无可用模型、模型超时和模型返回失败场景 |
| 数据隔离 | 使用专用测试环境、测试账号和测试项目，禁止在真实用户项目中执行破坏性用例 |
| 日志权限 | 测试负责人可查看 Web、Celery 和任务日志，但普通测试人员不应获得服务器管理权限 |

### 3.2 部署准入检查

开始 UI 测试前必须满足：

- `GET /api/health/live/` 返回 200；
- `GET /api/health/ready/` 返回 200，数据库和 Redis 检查通过；
- 数据库迁移已执行且无待迁移项；
- 首页静态资源无 404，页面展示的前端版本与本次发布一致；
- Celery worker 正常，能够执行一个最小测试任务；
- 至少完成一次管理员和普通用户登录；
- 浏览器 Console 在空闲状态无持续报错。

任一准入项失败，应停止全量测试并先修复环境。

## 4. 人员分工建议

每个工作包可以独立分配。负责人应执行本包全部 P0/P1 用例，并负责相关缺陷的回归。

| 工作包 | 模块 | 用例前缀 | 建议工作量 | 依赖 |
|---|---|---|---|---|
| A | 部署冒烟、账号、导航、项目 | `DEP/AUTH/NAV/PROJ` | 中 | 无 |
| B | 索引导入、解析、去重 | `SP/SD` | 大 | 已有账号和项目 |
| C | 纳排标准、自定义字段、AI 初筛 | `SC/SAI` | 大 | B 产出的去重数据 |
| D | 人工审阅、初筛导出 | `SR/SE` | 大 | C 产出的筛选结果 |
| E | 质量评价导入、方法选择、AI 评价 | `QU/QM/QAI` | 大 | 完成初筛或准备 PDF |
| F | 质量人工审阅、图表、报告导出 | `QR/QC/QE` | 大 | E 产出的评价结果 |
| G | 个人中心、额度、反馈 | `BILL/FB` | 中 | 管理员准备配额和兑换码 |
| H | 管理员权限、运维和优雅停机 | `ADM/OPS` | 中 | 独占测试时段 |
| I | 多用户/项目隔离、并发、异常恢复 | `ISO/NET` | 大 | A～H 基线通过 |
| J | 性能、兼容性、可用性、最终回归 | `PERF/COMP/REG` | 大 | 全流程功能通过 |

分工规则：

- 每名测试人员使用独立账号和以姓名缩写开头的项目；
- 除 `ISO` 专项外，不允许多人同时操作同一项目；
- `OPS` 会改变整个平台状态，只能由一名负责人在约定窗口执行；
- AI 和 4,000 篇文献用例应错峰，避免压测影响普通功能结论；
- 每包至少由另一人交叉复核一条核心主流程。

## 5. 测试账号与数据准备

### 5.1 账号矩阵

| 账号 | 条件 | 用途 |
|---|---|---|
| `admin_test` | 超级管理员/管理员，无限或充足额度 | 管理员全项目访问、运维、后台配额设置 |
| `user_a` | 普通用户，并发 2，配额充足 | 标准主流程 |
| `user_b` | 普通用户，并发 16，配额充足 | 并发任务和隔离测试 |
| `user_low_credit` | 余额不足以完成一次 AI 任务 | 额度不足 |
| `user_zero_quota` | 项目数或存储配额为 0 | 配额边界 |
| `user_disabled` | 后台设为不可登录 | 禁用账号 |

通过 Django 管理界面分别调整普通用户的 AI 并发数、项目配额和存储配额，并保留修改前后截图。

### 5.2 文献与文件矩阵

准备下列固定夹具，并记录预期篇数、重复数和关键字段：

- 小数据集：14 篇，包含纳入、排除和模型冲突样本；
- 中数据集：100～300 篇，用于分页、搜索和任务状态；
- 大数据集：4,000 篇，用于解析、去重、内存和结果查询性能；
- 每种受支持索引格式：`.ris`、`.bib`、`.nbib`、`.xml`、`.ciw`、`.enw`、`.txt`、`.doc`、`.docx`；
- TXT 编码：UTF-8、UTF-8 BOM、UTF-16 LE/BE、GB18030；内容包含中英文、重音字符和 emoji；
- ENW：同时含地址字段和会议/其他相近字段，专门核对导出 `Address` 列；
- 异常文件：0 字节、截断文件、错误扩展名、扩展名大小写、超限文件、同名不同内容、不同名相同内容；
- PDF：文本型、扫描型、中文、加密、损坏、空白、多栏、超长、接近大小限制；
- 图表名称：`A`、普通英文、普通中文、100 字符中文、100 字符英文、特殊字符和重复名称；
- AI 结果：全部一致、部分冲突、全部失败、部分失败、超时、被暂停后恢复。

所有下载验证必须和原始夹具做文件大小、编码及关键字段对照，不能只看“能下载”。

## 6. 执行与记录规范

### 6.1 优先级

| 优先级 | 定义 |
|---|---|
| P0 | 发布阻断：无法登录、核心流程无法完成、跨用户数据泄漏、数据损坏、无法安全停机 |
| P1 | 核心功能明显错误或无合理绕行方式，任务状态长期错误，导出内容错误 |
| P2 | 有绕行方式的功能问题、错误提示不准确、局部兼容或易用性问题 |
| P3 | 纯视觉、文案或低频轻微问题 |

### 6.2 单条用例记录

复制以下模板到测试记录中：

```text
用例编号：
执行人/时间：
环境/版本/浏览器：
账号/项目/测试数据：
结果：通过 / 失败 / 阻塞 / 不适用
实际结果：
证据：截图、录屏、Network 请求、Console、task_id
缺陷编号：
```

录屏不是默认要求。只有闪烁、时序竞争、重复跳转、短暂错误提示等截图无法表达的问题才需要录屏。

### 6.3 缺陷最低信息

- 标题包含模块和现象，不写“功能有问题”；
- 给出最短可复现步骤、发生概率、账号角色、项目 ID 和数据夹具；
- 异步问题附任务 ID、开始/结束时间和最后可见进度；
- 文件问题附原文件和下载文件；
- 权限问题说明当前账号、目标数据实际归属；
- 不在缺陷中粘贴密码、Cookie、API Key 或完整敏感文献内容。

### 7.1 部署与基础冒烟（DEP）

| 编号 | 优先级 | 场景与操作 | 预期结果 |

|---|---|---|---|

| SP-014 | P1 | 解析失败后查看日志并重试 | 可读错误与真实原因一致，重试不会叠加旧的错误数据 |
| SP-015 | P2 | 长文件名、中文文件名、特殊字符文件名 | 列表不撑破布局，下载名正确，无路径或编码问题 |

### 7.6 文献初筛：去重（SD）

| 编号 | 优先级 | 场景与操作 | 预期结果 |
|---|---|---|---|
| SD-001 | P0 | 对已知重复夹具执行去重 | 原始数、保留数、重复数与预期一致，详情可展开 |
| SD-002 | P0 | 对 4,000 篇数据执行去重 | 任务最终完成；进度不是永久“已扫描 0%”；完成态自动显示无需刷新 |
| SD-003 | P1 | 无重复、全部高度重复、只有 1 篇、0 篇 | 统计正确；0 篇时阻止无意义任务并给出提示 |

## 8. 端到端主流程验收

详细模块通过后，由非模块原执行人完成以下串联流程：

### REG-001：标准初筛流程（P0）

1. 普通用户登录并创建项目；
2. 上传包含 ENW/TXT 的索引文件并下载原文件核对；
3. 解析、去重，设置默认和自定义纳排标准/字段；
4. 用两个 AI 模型执行筛选，暂停并恢复一次；
5. 处理冲突、补充备注，其余未审结果按 AI 结论；
6. 导出 XLSX 和 RIS，核对篇数、决定、字段、编码及 Address；
7. 刷新并重新登录，确认全部状态仍存在。

### REG-002：标准质量评价流程（P0）

1. 从初筛纳入结果导入 QA；
2. 上传全文，批量指定 QUADAS-2/NOS；
3. 启动 AI 评价，制造一次失败后只重评失败项；
4. 人工修改信号问题并确认；
5. 设置短/长自定义名称，生成横向和纵向交通灯图；
6. 下载图片和 XLSX，核对正圆、符号大小及首个“汇总统计”Sheet；
7. 刷新后确认名称、图表和评价结果保持。

### REG-003：多人并发与管理员流程（P0）

1. `user_a/user_b` 在各自项目同时去重和 AI 筛选；
2. 管理员依次观察两项目进度并访问结果；
3. 验证普通用户互相无法访问；
4. 从后台调整两用户不同并发数和配额；
5. 再次运行任务，确认配置和结算分别生效。

### REG-004：优雅停机与升级恢复（P0）

1. 保持一个普通用户在线并运行一项 AI 任务；
2. 管理员进入排空，验证禁止新任务；
3. 暂停或等待存量任务结束，确认安全停机；
4. 执行停机、升级和 `--no-build` 启动；
5. 健康检查通过并恢复 normal；
6. 用户重新登录，确认任务和数据无损，继续完成流程。

## 9. 发布验收标准

同时满足以下条件才可建议上线：

- 所有 P0 用例通过；
- P1 用例通过率 100%，或仅剩有明确规避方案且经负责人书面接受的问题；
- 不存在跨用户/跨项目数据泄漏、重复扣费、文件损坏、任务永久锁死；
- Chrome 全流程和 Edge/Firefox/Safari 冒烟通过；
- 4,000 篇数据专项无浏览器崩溃或不可恢复的服务内存问题；
- `REG-001`～`REG-004` 全部通过；
- 所有失败用例均有关联缺陷、负责人和回归结论；
- 测试完成后清理测试项目、上传文件、运行任务和临时维护通知。
