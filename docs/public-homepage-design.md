# 平台公开首页设计与实施方案

> 状态：实施基线  
> 日期：2026-09-14  
> 范围：公开首页、公开导航、登录/注册入口与应用路由分流  
> 原则：只新增展示层，不改变现有业务接口、工作区状态与数据模型

## 1. 背景与目标

当前根路径 `/` 直接指向需要登录的项目列表，未登录访问时会跳转 `/login`。这对内部系统足够，但不适合对外介绍产品：访客无法在注册前理解平台解决什么问题、具备哪些能力、工作流如何组织以及为何值得信任。

本次增加一个独立的公开首页，目标是：

1. 访问域名根路径时先看到产品首页，而不是登录界面。
2. 用简洁、可信的方式展示平台已经具备的核心能力。
3. 为登录和注册提供清晰入口。
4. 保持与现有平台一致的靛蓝—紫色品牌色、卡片、圆角和科研工具气质。
5. 不修改任何后端接口、数据库模型、任务流程或权限规则。
6. 登录后的项目列表、工作区、个人中心和运维页面行为保持不变。

## 2. 参考产品分析

### 2.1 Rayyan

Rayyan 首页的主要结构为：

- 顶部产品导航和醒目的免费开始入口。
- 首屏直接表达“系统评价平台”的品类定位和使用价值。
- 使用产品数字、机构标识等社会证明建立信任。
- 通过完整工作流展示产品覆盖范围。
- 使用审计性、透明性、可复现性、规模化、速度和易用性等价值支柱解释差异。
- 中后段使用产品功能卡、客户评价和重复 CTA 完成转化。

可借鉴内容：明确品类、首屏双 CTA、工作流展示、可信度说明、页面末尾再次行动召唤。

不直接照搬内容：未经验证的客户数量、机构 Logo、节省比例、合规认证和用户评价。

### 2.2 Living EBM

Living EBM 首页的主要结构为：

- 使用中文科研语境表达方法学严谨性。
- 首屏嵌入接近真实产品的界面化演示，而不是使用通用科技插画。
- 用阶段导航串联系统评价全流程。
- 每个阶段同时说明痛点、能力和可见结果。
- 单独解释结果可复核、存疑转人工、数据可溯源等可信机制。

可借鉴内容：科研用户熟悉的中文表达、产品界面预览、阶段式叙事、可靠性解释。

不直接照搬内容：当前平台尚未实现的选题注册、联网检索、自动全文获取、统计分析和报告生成。

## 3. 产品定位与首页信息架构

首页使用以下定位：

> AI 辅助的系统化文献筛选与质量评价平台

核心价值表达：

> 从文献导入、去重、纳排标准到 AI 初筛、人工复核与质量评价，把重复工作交给系统，把最终判断留给研究者。

页面信息架构：

1. 顶部导航：品牌、核心能力、工作流程、可靠性；未登录时展示登录与免费开始，已登录时展示工作台与个人账户菜单。
2. Hero：品类定位、价值主张、双 CTA、产品界面预览。
3. 价值条：结构化流程、多模型交叉验证、人工复核优先、操作过程留痕。
4. 核心能力：六项当前已具备的能力。
5. 工作流程：文献初筛七步与质量评价流程。
6. 可靠性：可复核、可追踪、任务可恢复、项目隔离。
7. 最终 CTA：进入登录或注册。
8. 页脚：产品名称、核心锚点和版权信息。

## 4. 内容边界

### 4.1 本次允许展示的已实现能力

- 项目化管理。
- 文献文件导入与解析。
- 文献去重。
- 纳排标准维护。
- 自定义提取字段。
- 单模型或多模型 AI 初筛。
- 多模型分歧识别。
- 人工纳入、排除、待定及分歧裁定。
- 初筛结果导出。
- 从初筛导入质量评价文献。
- PDF 全文上传。
- 质量评价方法配置。
- AI 质量评价、人工复核、图表和 Excel 导出。
- 任务进度、暂停、恢复和操作日志。
- 用户资源配额与积分消耗基础设施。

### 4.2 本次不宣传的能力

- 尚未完成的文献检索、文献复筛、通用数据提取和 Meta 分析。
- 团队协作、双人盲法筛选或机构席位。
- 自动全文获取。
- PRISMA 自动生成。
- 未取得的合规认证。
- 未经数据证明的用户数、机构数、准确率和节省时间比例。
- 尚未正式上线的价格、套餐和支付能力。

## 5. 视觉设计

### 5.1 设计方向

- 延续现有平台的 `#6366f1` 靛蓝与 `#8b5cf6` 紫色渐变。
- 页面背景以浅灰白和极淡紫色光晕为主，避免与应用工作区产生割裂。
- 使用高密度但克制的产品界面卡片替代图库图片。
- 圆角保持在 10～24px，阴影轻量，突出专业工具而非娱乐产品。
- 正文优先使用系统字体、`PingFang SC` 和 `Microsoft YaHei`，不新增字体网络依赖。
- 仅使用已有 Font Awesome 图标和 CSS 图形，不新增图片资源与版权风险。

### 5.2 首屏预览

首屏右侧使用静态产品预览，表达真实工作方式：

- 顶部显示项目名称和七步初筛进度。
- 左侧展示纳排标准摘要。
- 中间展示 AI 对文献的纳入/排除结果。
- 右侧展示多模型结论及“需人工复核”的分歧状态。
- 所有内容为明确的演示数据，不与真实项目或后端 API 连接。

### 5.3 响应式设计

- `>= 1024px`：Hero 双栏，功能卡三列，流程双栏。
- `768px～1023px`：Hero 仍可双栏但缩小预览，功能卡两列。
- `< 768px`：导航收敛、Hero 单栏、功能卡与流程单列。
- `< 560px`：隐藏非关键锚点导航，仅保留品牌、登录和主要 CTA。
- 支持 `prefers-reduced-motion`，关闭进入动画和漂浮效果。

## 6. 路由设计与兼容策略

| 路径 | 页面 | 权限 |
|---|---|---|
| `/` | 新增公开首页 | 无需登录 |
| `/login` | 现有登录/注册页 | 无需登录；已登录时跳项目列表 |
| `/projects` | 原项目列表首页 | 需要登录 |
| `/workspace/:projectId` | 原项目工作区 | 需要登录 |
| `/profile` | 原个人中心 | 需要登录 |
| `/operations` | 原运维页 | 需要管理员 |

兼容策略：

- 保留原项目列表路由名 `Home`，只把路径从 `/` 调整为 `/projects`，降低现有按名称跳转代码的变更面。
- 新公开首页路由名使用 `Landing`。
- 登录成功且没有 `redirect` 参数时进入 `/projects`。
- 工作区返回、顶部品牌、个人中心返回均进入 `/projects`。
- 未登录直接访问工作区时仍跳转 `/login?redirect=原路径`。
- 已登录访问公开首页时不强制跳转，首页 CTA 自动改为“进入工作台”。
- 已登录首页提供个人中心、我的项目和退出登录入口；退出后保留在公开首页。
- 注册 CTA 使用 `/login?mode=register`，登录页读取该参数并默认打开注册 Tab。

## 7. 文件组织

遵守现有前端 feature 结构：

```text
web/src/features/landing/
├── content.js
├── components/
│   ├── LandingHeader.vue
│   └── ProductPreview.vue
└── views/
    └── LandingView.vue
```

- `content.js`：纯展示数据，便于后续产品文案修改。
- `LandingHeader.vue`：公开导航、移动端收敛和登录状态 CTA。
- `ProductPreview.vue`：首屏静态产品界面演示。
- `LandingView.vue`：页面区块装配及页面级样式。
- 不向 `shared` 放入首页专属组件，防止公共层被营销页面反向污染。

## 8. 无侵入实现约束

1. 不调用新增后端接口。
2. 不创建 migration。
3. 不修改项目、任务、筛选、质量评价、反馈或计费 Store 的状态结构。
4. 不修改业务 API 契约。
5. 不在公开首页挂载真实项目数据。
6. 反馈组件仍遵循原规则：仅登录后的非管理员页面可用。
7. 系统维护状态与会话初始化保持原逻辑。
8. 路由变更必须覆盖所有原先硬编码返回 `/` 的内部入口。

## 9. 验收标准

### 9.1 功能验收

- 未登录访问 `/` 能看到公开首页，不跳登录。
- 首页登录按钮进入 `/login`。
- 首页免费开始按钮进入 `/login?mode=register`，并默认显示注册表单。
- 登录成功默认进入 `/projects`。
- 未登录访问 `/projects` 或工作区仍进入登录页面。
- 已登录访问 `/login` 自动进入 `/projects`。
- 已登录访问 `/` 可以看到“进入工作台”入口。
- 已登录用户可以从首页进入个人中心、项目列表或退出登录。
- 项目列表、工作区、个人中心和管理员运维路由保持可用。
- 所有内部“返回项目列表”入口均指向 `/projects`。

### 9.2 视觉与可访问性验收

- 桌面、平板和移动端无横向溢出。
- 页面只存在一个一级标题。
- 锚点区块具有稳定 ID，键盘可以访问所有按钮和链接。
- 颜色对比和焦点样式可辨认。
- 减少动态效果系统设置能够生效。
- 不依赖新增的大图、视频或第三方脚本。

### 9.3 工程验收

```bash
cd web
npm test
npm run lint -- --quiet
npm run build
```

并执行 Django 基础检查，确认 SPA fallback 不受影响：

```bash
venv/bin/python manage.py check
```

## 10. 待用户确认项

以下事项不会阻塞本次开发，先使用括号内默认方案：

1. 正式产品名称（默认沿用“科研 Meta 平台”）。
2. 是否已有品牌 Logo（默认使用现有烧瓶图标和渐变方形标识）。
3. 首屏主文案最终版本（默认强调“AI 辅助、判断可复核”）。
4. 是否展示“免费”承诺（默认按钮写“免费开始”，不承诺永久免费或具体赠送额度）。
5. 是否开放价格入口（默认不展示，等待计费方案正式上线）。
6. 是否提供公开联系方式、备案号、用户协议和隐私政策链接（默认暂不虚构，仅保留产品导航与版权）。
7. 尚未实现的阶段是否在首页显示 Roadmap（默认不展示，以免用户误判已经可用）。
8. 是否需要英文版首页（默认仅中文）。
